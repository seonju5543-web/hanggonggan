# 한대장 사내 보고서 양식 (report-kit)

2026-11-17 개발자 지시(이선주): *"사내 보고서 양식을 리서치한 후 우리 앱에 맞는 사내 보고서 양식을 만들어서 적용해줘. 해당 양식은 다음에도 사용될 수 있어."*
검토 · 결과 · 기획 보고서처럼 **사람에게 돌려 보는 PDF 문서**는 이 양식으로 만든다. 세션이 따르는 순서는 스킬 `.claude/skills/internal-report/SKILL.md`.

```bash
node tools/report-kit/build.mjs <명세.json> --out <보고서.pdf> --png <미리보기 폴더>
```

- 글꼴은 앱과 같은 Pretendard. `REPORT_FONT_DIR` → `node_modules/pretendard` → 없으면 `npm pack pretendard@1.3.9` 로 임시 폴더에 받는다.
- 브라우저는 playwright(전역 설치도 찾는다) · `CHROME_PATH` 로 바꿀 수 있다.
- 🔴 보고서 PDF · 명세는 **커밋하지 않는다** — 공개 저장소이고 문서는 사내 한정이다. 세션 임시 폴더에 만든다.

## 양식의 근거 (조사한 것)

| 무엇 | 출처 | 양식에 들어간 곳 |
|---|---|---|
| 항목 부호 차례 `Ⅰ.` → `1.` → `□` → `○` → `-` → `·` | 정부 보고서 골격(국가기록원 실측 정리) · 「행정업무의 효율적 운영에 관한 규정 시행규칙」 제2조 · 행정안전부 「행정업무운영 편람」 | 장 번호(로마숫자) · 소제목(`1.`) · 개조식 항목(`points`) |
| 결재란(작성 · 검토 · 승인) · 문서 번호 · 시행일 | 행정업무운영 편람의 결문 구조 | 표지 결재란 · 문서 정보 표 |
| 두괄식 · 한 쪽 요약(목적 · 배경 · 결론 · 요청) | 기업 보고서 작성법(읽는 사람 중심 · 용건 → 이유 → 근거) | 「보고 개요」 쪽 |
| 개조식(종결어미 생략 · 명사형) | 같은 자료 | 쓰는 법 규칙 |
| `※` 참고 · `붙임` · 문서 끝 `끝.` | 공문서 관행 | `note` 블록 · 붙임 장 · 끝 표시 |
| 보안 등급 표기 | 사내 문서 관행 | 표지 · 모든 쪽 머리글 · 바닥글 |

색과 로고는 앱에서 왔다: 남색(`style.css` primary `#222c3b` · 아이콘 바탕 `#101d3d`) · 파랑(accent `#2f4d78`) · 금색(학사모 술 `#b8912f`) · 로고는 `icons/icon.svg` 그대로.

## 쪽 구성 (모든 보고서가 같다)

1. **표지** — 로고 · 서비스 이름 · 보안 등급 / 문서 종류 · 제목 · 부제 / 문서 정보 표 · 결재란(작성 · 검토 · 승인)
2. **보고 개요** — 목적 · 배경 · 현황 · 검토 사항 · 요청 사항을 한 쪽에(두괄식) + 핵심 수치 칸
3. **장(Ⅰ · Ⅱ · Ⅲ …)** — 장마다 새 쪽. 장 머리(번호 칸 + 제목 + 한 줄 요약) 아래 블록
4. **붙임** — 출처 · 확인 방법 / 용어 풀이 / 문서 이력 → `끝.`

본문 쪽은 **모두 같은 틀**이다: 머리글 왼쪽 `로고 한대장 | 문서 제목`, 오른쪽 `문서 번호 · 보안 등급`, 바닥글 왼쪽 보안 문구, 오른쪽 `- 쪽 / 전체 -`. 표지에는 머리글 · 바닥글이 없다.

## 쓰는 법 (내용 규칙)

- **개조식**으로 쓴다: "~함 · ~임 · ~필요" 또는 명사로 끝낸다. 한 항목에 한 가지.
- **두괄식**: 보고 개요에 결론 · 요청을 먼저 둔다. 장 머리 한 줄 요약도 결론부터.
- **확인한 것만** 단정한다. 확인 못 한 것은 '미확인'이라 적고 마지막 장에 모은다(CLAUDE.md 원칙 5).
- **판단과 사실을 섞지 않는다**: 결정을 구하는 문서면 우열 · 권장 표시 없이 장단점만 둔다(2026-11-17 지시).
- 숫자는 원천에서 세고 `appendix.sources` 에 어디서 셌는지 적는다. 크기를 비교하는 숫자는 `bars` 로.
- 전문 용어는 풀어 쓰고 붙임의 용어 풀이에 모은다(개발자는 코드를 모른다).
- 열쇠 값 · 개인 이메일은 넣지 않는다.

## 명세 꼴

```jsonc
{
  "meta": {
    "docType": "검토 보고서",               // 결과 보고서 · 기획 보고서 · 회의 결과 …
    "docNo": "HDJ-검토-2026-001",           // HDJ-<종류>-<연도>-<순번>
    "title": "제목\n두 줄도 됨", "runningTitle": "머리글에 들어갈 한 줄 제목",
    "subtitle": "부제", "dept": "백엔드", "date": "2026. 11. 17.",
    "security": "사내 한정",                 // 표지 · 머리글 · 바닥글
    "fields": [["문서 번호", "…"], ["보고 일자", "…"], ["요청", "…"], ["작성", "…"], ["검토 대상", "…"], ["문서 상태", "…"]],
    "approvals": [{ "role": "작성", "name": "Claude" }, { "role": "검토", "name": "" }, { "role": "승인", "name": "" }],
    "revisions": [{ "ver": "1.0", "date": "…", "note": "최초 작성" }]
  },
  "overview": [{ "label": "목적", "text": "한 줄" }, { "label": "현황", "text": ["항목", "항목"] }],
  "keyFigures": [{ "label": "…", "value": 5, "unit": "회", "note": "…", "tone": "bad|warn" }],
  "chapters": [{ "title": "장 제목", "summary": "한 줄 요약", "blocks": [ /* 아래 */ ] }],
  "appendix": { "sources": ["**무엇** — 어디서 어떻게"], "glossary": [["용어", "뜻"]] }
}
```

| 블록 `type` | 쓰임 | 칸 |
|---|---|---|
| `subhead` | 장 안의 소제목 `1.` `2.` (자동 번호) | `text` |
| `points` | 개조식 항목 □ → ○ → - → · | `items`: 문자열 또는 `{ text, sub: [...] }` · `title` |
| `table` | 문장 표 | `columns[{label,width}]` · `rows[[…]]` · `title` · `note` |
| `bars` | 크기 비교 막대 | `items[{label,value,display?,tone?:'muted'|'gold'|'bad'}]` · `unit` · `max?` |
| `figures` | 숫자 칸 | `items[{label,value,unit,note,tone}]` · `cols` |
| `compare` | 장단점 나란히 | `left{label,items}` · `right{label,items}` · `title` |
| `steps` | 진행 순서 | `items[{title,note,owner}]` |
| `note` | `※` 참고 | `text` · `tone:'warn'` |
| `text` | 문단 | `paras[]` |

글 안에는 `**굵게**` · `` `코드` `` · 줄바꿈(`\n`)을 쓸 수 있다.
