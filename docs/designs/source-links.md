# 원문 링크 — 누르면 정말 그 공고가 열리는가 (2026-10-03 · P0)

> 개발자 보고: *"공고 내 원문공고를 클릭했을 때 해당 공고의 페이지로 이동하지 않고 재단이나 장학금 페이지 전체가
> 표시되는 상황이 발생하여 사용자들이 신청에 어려움이 있다"* — *"장학금 뿐만 아니라 대외활동 공모전 뉴스 등 앱 전반에
> 거쳐 일어나고 있는 매우 심각한 사태"*.
> 경위·실측 숫자는 `SESSIONS.md` 「원문 링크가 공고가 아니라 홈페이지·목록을 열던 사고」. 이 문서는 **지금 어떻게 돌아가는가**만 적는다.

## 1. 왜 일어났나 — 다섯 갈래 (조사 7갈래 · 반박 검증을 거친 것만)

| # | 무엇이 | 어떻게 학생을 엉뚱한 곳으로 보냈나 |
|---|---|---|
| ① | **화면이 링크 이름을 주소 글자만 보고 정했다** | `#n-` 표식이 없으면 무조건 '원문'. 이름 정하는 곳이 일곱 군데라 서로 달랐다 — 층2(재단 홈페이지)를 아는 곳은 하나뿐이어서 신청 내역은 재단 홈페이지를 '공고 원문 보기'라 불렀다. 대외활동 시트는 기관 홈페이지도 '원문에서 신청하기'. |
| ② | **고치는 로봇이 멀쩡한 링크를 망가뜨렸다** | 링크 사냥꾼 순찰이 게시판 행 잡티(`학생지원팀 2026-09-02 1,076`)나 사람이 다듬은 앱 이름으로 제목을 대조해 '제목 불일치'를 내고, **멀쩡한 상세 주소를 목록 표식으로 덮어썼다**(옛 주소를 남기지 않았다). 같은 날 커밋 제목은 '원문 주소 0건 확보'. |
| ③ | **목록 주소에 번호만 붙인 것을 원문으로 저장했다** | 가천·고려(`subview.do?nttId=`)·서울교대(`selectNttList.do?…nttId=`) — 서버가 번호를 무시하고 목록을 준다(로봇이 받아 둔 본문이 번호만 다른 주소끼리 글자 하나 안 달랐다). 확인 단계는 '목록에도 그 제목이 있다'를 못 걸렀다. |
| ④ | **주소에 HTML 기호(`&#038;`)가 박혀 글 번호가 잘렸다** | 서울대 — 브라우저는 `#038;…uid=392` 를 조각으로 읽어 서버에 글 번호를 안 보낸다 → 메뉴 화면. |
| ⑤ | **아무도 학생처럼 새 탭으로 열어 확인한 기록을 남기지 않았다** | 순찰은 정식 등록·옛 피드만, 하루 20건 남짓, 목록 판별 없이(다른 글 제목을 빈 목록으로 넘겼다). 재단·지자체·대외활동·소식·층2는 **한 번도** 안 열어 봤다. 주간 복구 로봇은 8월 14일부터 한 학교에 묶여 7주 동안 0건(초록불). |

## 2. 지금의 장치 — '판정 한 곳 · 확인 로봇 · 이름 한 곳'

```
 데이터(registered·notices/학교별·external·activities·news·kosaf-open)
        │
        ├─ 원문 링크 확인 로봇 (collector/link-check.mjs · 매일)  ── 학생처럼 새 탭(쿠키·리퍼러 없음)으로 연다
        │     판정은 collector/link-landing.mjs 한 곳(post · list · home · login · gone · other · unread)
        │     🔴 주소를 고치지 않는다 — 판정만 적는다
        │     → collector/link-check-state.json(전부) → data/link-check.json(확정된 문제만 · 앱이 받는다)
        │
        └─ 화면 (source-link.js 한 곳 — 상세·금액·신청 내역·카드·활동 시트·도우미·제출처)
              linkKind = 꼴(표식·목록+번호·홈페이지) + 로봇 확정 → 이름
```

- **확정은 다른 날 두 번** — 한 번 막혀 껍데기를 받은 것으로 멀쩡한 링크를 문제라 부르지 않는다(동국대 12건 오판의 교훈).
  한 사이트에서 '제목이 안 보이는' 문제가 절반을 넘으면 막힘으로 보고 판정하지 않는다(단 '제목은 보이는 목록'은 그대로 — 가천처럼 게시판 통째로 목록인 곳이 빠지면 안 된다).
- **제목 먼저, 로그인 벽은 나중** — 페이지 머리의 회원 로그인 상자 때문에 멀쩡한 공고가 '로그인 요구'가 되던 것.
- **다른 글 제목을 반드시 넘긴다** — 넘기지 않으면 목록을 영영 못 알아본다.

| 보통(page) | 문제로 확정된 적 없음 | 원문 공고 ↗ | 공고 원문 보기 ↗ | 원문 보기 ↗ | 원문에서 신청하기 ↗ |
| 목록(list) | `#n-` 표식 · 목록+번호 꼴 · 로봇이 목록 확정 | 게시판 목록 ↗ + 찾을 제목 | 게시판 목록 열기 ↗ | 게시판 목록에서 보기 ↗ | 게시판 목록에서 보기 ↗ |

🔴 '보통'의 글자는 2026-10-03 이전 그대로다. 새로 생긴 글자는 **홈페이지·문제** 두 줄뿐 — 개발자 확인 대상.

- **맨 도메인**(`https://x.kr/` — 길이 없는 주소)은 홈페이지로 단정하지 않는다(`root` → 보통 이름). 공모전 전용 사이트(`maicon.kr/` 등)는
  첫 화면이 곧 그 공모전이다. 정말 기관 첫 화면이면 확인 로봇이 열어 보고 확정한다. 꼴로 홈페이지라 부르는 것은 짧은 경로의 **첫 화면 파일 이름**(`HOME_FILE_RE`)일 때뿐.
- **제출처 이름은 명사**(`officialChannel` — 'OO에서 공식 제출을 마치셨나요?' 안에 들어간다) · 할 일(제목으로 찾기)은 링크 옆 안내 문장이 말한다.
- **캐시 엇갈림** — 새 app.js 가 옛 index.html(서비스워커 캐시)과 만나 source-link.js 가 없으면, 글자 없는 자리표로 버티고 파일을 직접 불러 다시 그린다(이름 글자는 베끼지 않는다).

### 원문 바로잡기 (2026-10-04 · 개발자 지시 *"원문 공고 링크를 최대한 어떻게든 찾을 방법"* · *"관리자 페이지에 원문 공고를 추가할 칸"*)

데이터 파일은 로봇이 날마다 다시 만든다(실시간 공고·대외활동 API·층2 재단은 통째로) — 거기에 진짜 주소를 고쳐 써 두면 다음 실행에 사라진다.
그래서 **바로잡은 원문은 따로 적고, 링크 이름 한 곳(`source-link.js` ⑥)이 먼저 읽는다**. 화면·도우미·제출처·화면 확인 도구가 전부 그 한 곳을 거친다.

```
 사람  관리자 「할 일 › 원문 링크 손볼 것」 → tools/admin-apply.mjs linkFix → data/link-fixes.json   (늘 이긴다)
 로봇  collector/link-candidates.json(사람·세션이 적은 후보) + 우리 기록에서 스스로 찾은 후보(같은 제목의 진짜 주소 · 재단 게시판 글)
         → 원문 링크 확인 로봇 ⓪단계가 학생처럼 열어 acceptCandidate(사이트·제목·회차·사업·기관·겹침)를 통과한 것만
         → data/link-check.json fix   (🔴 지금 링크가 이미 그 공고면 쓰지 않는다)
 앱    linkFixFor → effectiveLinkUrl — 바로잡은 주소도 로봇이 날마다 열어 보고, 문제면 「(확인 필요)」
```

- **열쇠**: 정식 등록·층2(`kosaf-<코드>`)·id 가 있는 공공 API 글은 `id:` · 나머지 피드 글은 `u:<지금 주소>`(로봇이 그 글 주소를 바꾸면 '대상 없음' — 관리자 화면 ⑥에 뜬다).
- **회차**: 층2만 `round`(= 마감). 재단 코드는 해마다 그대로라 지난 회차 공고를 올해 것으로 보이면 가짜 공지다(원칙 6).
- **후보를 더하는 법**: `collector/link-candidates.json` 에 줄을 적어 기본 브랜치에 push 하면 후보만 확인하는 실행이 한 번 돈다(`LINK_CHECK_MODE=candidates`). 로봇은 그 파일을 읽기만 한다.
- **링크를 만드는 로봇도 고쳤다**: 서울교대 data-id 줄 → 상세 주소(`ruleDetailCandidates` · 교내 소식 규칙 표를 같이 쓴다) · 경희 교내 소식은 정찰(10-04)로 GET 상세가 열림을 보고 목록 표식 → 글 주소 ·
  사냥꾼의 거짓 알림(#387 — 3단계에서 찾았는데 '막힘'으로 셈)과 깊은 글을 '사라짐'으로 적던 것 · 관리자가 넣은 원문은 사냥꾼·복구 로봇이 건드리지 않는다 · 공공 API 는 주소 칸을 점수로 고르고 확인된 문제 주소는 피한다.

## 3. 다시 생기지 않게 막는 것 (관문 「원문 링크 정직성」 · `verify/link-gates/*.mjs`)

- **core** — 규칙·판정 자체(실측 사례로: 서울대 `&#038;` · 층2 · 가천 목록+번호 · 전북 로그인 상자 · 동국 껍데기 · 두 날 확정 · 병합 순위).
- **app** — 화면이 이름을 source-link.js 에서만 받는가(이름 글자가 다른 파일에 남아 있으면 실패) · 진짜 화면 함수로 층2·홈페이지를 '원문'이라 부르지 않는가.
- **robot** — 확인 로봇이 다섯 묶음을 다 도는가 · 주소를 고치지 않는가 · 두 날 확정 · 워크플로 약속(시한·저장·실패 알림).
- **producers** — 순찰이 주소를 덮어쓰지 않는가 · 목록+번호 후보를 만들지 않는가 · HTML 기호 되돌림 · 복구 로봇의 낡은 고정(`onlyBoard`).
- **data** — 데이터 감사의 원문 링크 경고(`verify/link-audit.cjs` — 다섯 묶음 전부 · 경고만).
- **병합 순위** — 진짜 주소 > 목록 표식 > 목록 주소+번호(`collector/url-key.mjs preferNotice`). 사람이 고친 표식이 병합 때마다 되돌아가지 않게.
- **병합 상한** — 합집합 병합기는 수집기의 `capNotices` 를 부른다(박힌 200 때문에 339 → 200 으로 잘린 사고 · data ③).
- **학교별 파일 베끼기** — `patchUrlsBySchool` 은 링크 순위(`noticeUrlRank`)를 낮추는 쪽으로는 고치지 않는다(배포 직후 항공대 2건 사고 · producers ⑨).
- **로봇 깨우기** — 저장하는 push-to-run 로봇은 push 트리거에 브랜치를 건다(main 에서 뜬 사고 · robot ⓩ).
- **알림** — 주소가 고쳐진 옛 공고가 '새 공고'로 다시 울리지 않는다(알림 장부에 학교·제목 열쇠 + 수집일 규칙 · core ⑨).
- **화면 확인 도구** — `verify/what-shows.mjs` 가 카드의 한 줄 const 를 빠짐없이 떼어 온다(core ⑧).

🔴 실데이터에 기댄 검사는 관문에 두지 않는다(수집 로봇도 이 관문을 돈다 — 실데이터가 선을 넘는 날 그날 결과가 통째로 되돌려진다). 실데이터는 감사의 **경고**.

## 4. 아직 남은 것 (정직하게)

- **목록 표식(`#n-`)은 여전히 목록을 연다** — 이름이 정직할 뿐이다. 진짜 주소는 링크 사냥꾼(1단계 사냥)이 찾는다. 이번에 사냥꾼의 판정도 같은 판정기로 바꿨다.
  표식이 오래 남는 게시판은 게시판별 규칙(클릭형·POST형·API형 — 교내 소식의 `news-board-rules.mjs` 처럼)이 필요하다.
- **층2(KOSAF) 91건은 재단 홈페이지뿐이다** — 상세가 POST 전용. 대신 선발 공고문 사본(`data/kosaf-files/`)을 상세 시트에서 준다.
- **확인 로봇의 첫 확정은 이틀 뒤** — 다른 날 두 번 봐야 한다.
- ~~로봇이 '문제'로 확정한 링크를 사람이 고칠 길은 정식 등록만 있다~~ → 2026-10-04 관리자 「원문 링크 손볼 것」이 다섯 묶음 + 층2 모두 받는다(위 「원문 바로잡기」).
- **층2(KOSAF) 대부분은 아직 재단 홈페이지다** — 재단 게시판 글을 우리 기록에서 찾은 것은 다섯 곳뿐(웹 검색은 이번 회차 글을 거의 못 찾았다). 나머지는 관리자 화면 ④ 묶음에서 사람이 넣는다.
- 로봇 후보 확인의 첫 확정은 **배포 뒤 첫 실행**부터다(이미 그날 연 주소는 다음 날로 미룬다). 재단 사이트가 GitHub 의 컴퓨터를 막으면 '못 읽음'으로 남고 사람에게 넘긴다.
