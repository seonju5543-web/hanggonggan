# 신청서 글이 공고마다 달라지게 하는 법 — 검토 (2026-08-23)

> 개발자 질문: *"AI가 채우면 모든 공고에서 답변이 비슷해지고 '나를 뽑아주세요'를 어필할
> 특성이 없어질 것이 걱정된다. 인터넷에서 장학 자기소개서 예시문을 모아 AI에게 학습시켜
> 각 공고에 맞는 예시를 꺼내 참고하게 하면 어떤가? 미학습 양식이 생기면 유동적으로 검색해
> 학습·저장할 수 있나? 수집 로봇을 새로 만들어야 하나? API 사용은 최대한 피하고 싶다."*

**걱정은 옳다. 방법은 바꾸는 것을 권한다.** 아래가 근거다.

---

## 1. 결론 — 예시문 수집은 하면 안 된다

세 가지 이유가 각각 독립적으로 치명적이다.

### ① 🔴 장학재단은 표절률을 검사한다 — 예시문을 참고하면 학생이 떨어진다

조사 결과: *"장학재단에서는 표절률 검사를 엄격하게 진행"*하고,
표절 검사 도구는 *"AI 작성, 유사한 표현, 구조만 바꾼 문장도 적발"*한다.

그리고 인터넷에 공개된 장학금 자기소개서 예시문이 있는 곳(링커리어 커뮤니티·해피캠퍼스·
레포트샵·예스폼)은 **정확히 카피킬러가 크롤링하는 그 문서 더미**다.

> 즉, 예시문을 참고해 쓸수록 표절률이 **올라간다.**
> 우리가 만들어 준 서류가 학생을 떨어뜨리는 구조가 된다. 이건 개선이 아니라 사고다.

### ② 🔴 저작권 — 남이 쓴 글이고, 대부분 유료 판매 문서다

해피캠퍼스·레포트샵은 문서를 **팔아서** 돈을 버는 곳이다. 그 글을 긁어 저장하고
상업 서비스의 학습·참조 자료로 쓰는 것은 침해다. 무료 커뮤니티 글도 저작권은 작성자에게 있다.

### ③ 🔴 개발자가 걱정한 '획일화'를 오히려 **악화**시킨다

모든 학생이 같은 예시 더미를 참고하면 결과는 **수렴한다.** 지금보다 더 비슷해진다.
예시문은 차별화의 해법이 아니라 획일화의 원인이다.

---

## 2. 그런데 개발자가 원한 것은 옳다 — 차별화는 다른 데서 온다

"나를 뽑아주세요"가 되려면 두 가지가 글에 들어가야 한다.

| | 어디서 오는가 | 지금 상태 |
|---|---|---|
| **(가) 이 재단이 무엇을 보는가** | **공고 원문에 적혀 있다** | 갖고 있는데 **안 쓰고 있다** |
| **(나) 이 학생만의 사실** | 키워드 카드로 받는다 | 받고 있다 (더 받을 수 있다) |

조사에서 나온 말이 이걸 그대로 짚는다 —
*"자기소개서를 작성하기 전에 지원하는 장학재단의 비전, 목표, 선발 기준을 철저히 조사해야 한다."*

**그 조사를 학생 대신 해 주는 것이 우리가 팔 수 있는 것이다.** 남의 자소서를 베껴 주는 게 아니라.

---

## 3. 실측 — 재료는 이미 저장소 안에 있다

| 항목 | 실측 |
|---|---|
| 정식 등록 공고 | 195건 |
| 그중 **원문 전문이 저장돼 있는 것** | **181건** (`collector/extracted/notices-text.json`) |
| 양식이 연결된 공고 | 38건 |
| 그중 원문이 있는 것 | **38건 = 100%** |
| 그중 **재단이 무엇을 보는지 드러나는 줄이 있는 것** | **23건** |

실제로 뽑힌 줄 (원문 그대로):

```
삼일장학회  → 1. 목적: 어려운 환경과 조건으로 인해 학업 지속이 어렵지만,
              학업에 대한 강한 열정을 가지고 있으며, 학업성적이 우수하고 타인에…
가송재단    → 1. 재단명 : 가송재단 ( 동화약품 ㈜ 출연금으로 설립 )
숙명여자대학교 → 인재상 및 핵심역량
```

**그런데 지금 앱이 AI에게 보내는 공고 발췌는 평균 68자이고, 재단 관점 문장은 0건 들어간다.**
가진 재료를 안 쓰고 있는 것이다. 여기가 가장 싼 개선 지점이다.

---

## 4. 제안 — '재단 카드' (추가 API 호출 0회)

### 만드는 것
`collector/foundation-profile.mjs` — **규칙만 쓰는 무료 발췌기**(비용 0).
저장된 공고 원문에서 아래 네 가지에 해당하는 **줄을 원문 그대로** 뽑아
`data/foundations.json`으로 발행한다.

| 뽑는 것 | 예 |
|---|---|
| 설립 목적·취지 | "어려운 환경에도 학업 열정이 있는 학생을 돕는다" |
| 인재상 | "타인에 대한 배려와 나눔의 자세를 갖춘…" |
| 우선 선발 기준 | "가정형편이 어려운 자를 우선 선발" |
| 우대 사항 | "봉사활동 실적이 있는 자 우대" |

🔴 **지어내지 않는다.** 원문에 없으면 그 공고는 카드가 없다(원칙 8-1).
이건 이 저장소가 `extract-excerpts.mjs`에서 이미 쓰는 방식 그대로다.

### 쓰는 것
초안 서버가 지금 보내는 요청에 그 카드를 **같이 실어 보낸다.**
**호출 횟수는 그대로 1회다.** 입력이 300~600자 늘 뿐이다.

프롬프트에 한 줄을 더한다:
> *"이 재단은 「어려운 환경 속 학업 의지」와 「나눔」을 본다.
> 학생이 고른 키워드 중 그것과 이어지는 것을 앞세워 쓰고, 나머지는 뒤로 보내라."*

**결과**: 같은 학생이 같은 키워드를 골라도
삼일장학회에는 *역경 속 학업 의지* 쪽으로,
가송재단에는 그 재단이 적어 둔 관점 쪽으로 **다르게 쓰인다.**

### 비용
| | |
|---|---|
| 카드 만들기 | **0원** (규칙 발췌 · API 없음) |
| 쓰기 | 기존 호출에 입력 300~600자 추가 = **건당 +1~2원** |

## 5. 획일화를 막는 두 번째 장치 (역시 API 0원)

재단 카드는 '공고마다 다르게'를 만든다. '학생마다 다르게'는 따로 필요하다.

1. **각 키워드 세트의 자유 입력 칸을 맨 앞으로 올린다.**
   지금은 `기억나는 일 하나`·`생활 신조 한 줄` 같은 칸이 카드 끝에 있다.
   맨 앞에 두고 *"여기 한 줄이 합격을 가릅니다"* 라고 적으면 채우는 비율이 오른다.
2. **프롬프트에 못 박는다**: *"글의 첫 문단은 반드시 학생이 직접 쓴 문장에서 출발할 것.
   고른 보기(칩)만으로 첫 문단을 쓰지 말 것."*
   → 칩만 고른 학생끼리도 첫 문단이 갈린다.
3. **자유 입력이 하나도 없으면 분량을 줄인다.** 재료 없이 분량을 채우려면 지어내야 하는데,
   그건 `draft-guard.mjs`가 어차피 버린다. 짧고 진짜인 글이 길고 빈 글보다 낫다.

---

## 6. "미학습 양식이 생기면 인터넷 검색으로 학습" — 새 로봇이 필요한가

**필요 없다.** 이유:

- 우리에게 필요한 것은 **예시문이 아니라 그 재단의 관점**이고, 그건 **공고 원문에 있다.**
- 공고 원문은 **이미 매일 수집한다**(수집 로봇 2종 + 심층 수집). 새 양식이 등록되는 그 순간
  그 공고의 원문도 함께 들어온다. 즉 **'미학습 양식'이라는 상태가 사실상 생기지 않는다.**
- 검색 API도 필요 없다. 공고에 재단명·주관기관이 적혀 있다.

**원문에 재단 관점이 안 적힌 공고(38건 중 15건)만** 재단 홈페이지가 필요하다. 그건
새 로봇이 아니라 **기존 `deepfetch.mjs`에 '재단 소개 페이지 한 장'을 표적으로 추가**하면 된다
(첨부 원본을 받아 오는 그 통로를 그대로 쓴다). 링크 사냥꾼이 쓰는 브라우저 방식이 이미 있다.

> 정리: **로봇 신설 0개 · 검색 API 0개 · Claude API 추가 호출 0회.**

---

## 7. 정직하게 남는 한계

- **재단 관점을 못 찾는 공고가 38건 중 15건.** 그 공고는 지금과 똑같이 동작한다
  (빈칸이 되는 게 아니라 카드가 없을 뿐이다).
- **AI가 쓴 글이 AI 탐지에 걸릴 가능성은 남는다.** 이건 어떤 방법으로도 0이 되지 않는다.
  지금 방어는 화면에 **'초안이니 반드시 읽고 고쳐 제출하라'**고 적어 둔 것이다.
  여기에 **제출 전 표절 검사 안내**(카피킬러·워드바이스 무료 검사 링크)를 한 줄 붙이는 것을 권고한다 —
  학생을 실제로 지켜 주는 장치이고, 우리가 정직하다는 표시이기도 하다.
- 규칙 발췌라 엉뚱한 줄이 섞일 수 있다. 자격 요건 작업과 같은 방식으로
  **채점 도구를 따로 두어**(필터의 눈으로 필터를 채점하지 않는다) 매 실행 의심 줄을 올린다.
