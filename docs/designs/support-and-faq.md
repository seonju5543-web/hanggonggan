# 고객센터 · 자주 묻는 질문 강화 (2026-09-13)

개발자 지시: *"고객센터 기능을 설정에 추가하고 기존에 있는 FAQ기능은 강화하고 싶어. 커넥터 연결된
UI bowl을 통해 고객센터, FAQ에 들어간 후 사진처럼 아파트너 사례를 참고하여 …"*

## 1. 참고안에서 가져온 것 · 일부러 안 가져온 것

유아이볼에서 실제로 열어 본 것은 넷이다 — **아파트너**(개발자가 보내 준 화면), **라이프캐치**
(고객센터), **볼트업**·**쿠팡이츠**(자주 묻는 질문).

| 참고안 | 가져왔나 | 왜 |
|---|---|---|
| 아파트너 — 검색창 `질문을 입력해주세요` | ✅ | 앱의 `.search-box`(탐색 화면과 같은 부품)로 |
| 아파트너 — 갈래 칩 여러 줄 | ✅ | 다만 **접는다**(아래 3-③) |
| 아파트너 — 아코디언 | ✅ | 이미 있던 `<details class="faq-item">` 그대로 |
| 아파트너 — 「"…"에 대한 결과가 N개입니다」 | ✅ | 검색 중일 때만 |
| 아파트너 — 「검색결과가 없습니다」 + 안내 + 버튼 | ✅ | 버튼만 `1:1 문의하기` → **`고객센터 가기`** |
| 볼트업 — 질문 위 갈래 이름표 | ✅ | 목록을 훑는 것만으로 무엇에 대한 답인지 보인다 |
| 라이프캐치 — 「자주 찾는 질문 TOP 5」 번호 목록 | ✅ | 고객센터 첫 절 |
| 라이프캐치 — 「나의 문의 내역」 탭 | ❌ | **받아 두는 서버가 없다.** 눌러서 빈 화면이 나오는 탭이 가장 나쁘다(운영 원칙 1) |
| 아파트너 — `1:1 문의하기` 버튼 | ❌ | 같은 이유. 대신 지금 되는 길(대장님·메일)을 준다 |

🔴 **참고안을 베낀 것이 아니라 우리가 할 수 있는 것만 골랐다.** 칩의 선택 색도 아파트너의
파란 채움이 아니라 **앱이 이미 쓰는 `.filter-chip.active`** 를 그대로 쓴다 — 한 앱 안에서 칩이
두 가지 모양이면 그게 더 어색하다.

## 2. 고객센터에 넣은 넷 — 전부 지금 동작한다

1. **자주 찾는 질문 TOP 5** → 누르면 그 질문이 펼쳐진 FAQ 로 간다(`faqOpenQuestion`).
   목록은 `FAQ_TOP` 하나이고 **질문 글자로** 가리킨다(번호로 가리키면 순서가 바뀔 때 엉뚱한 게 뜬다).
2. **대장님(도우미)에게 물어보기** → `chat.js` 의 `chatOpen()` 을 그대로 부른다.
3. **문의 메일 쓰기** → `support-config.js` 의 `email` 이 채워졌을 때만 나온다.
4. **진단 정보 복사** → 앱 버전 · 설치 형태 · 알림 권한 · 로그인 여부 · 브라우저.

## 3. 되돌리지 말 것 (전부 만들면서 실제로 겪었다)

### ① 문의처는 비어 있는 것이 지금의 정답이다
`terms.html` 9번이 *"베타 기간에는 별도 문의처를 두지 않습니다. 서비스를 공개할 때 실제로 응대
가능한 주소를 이 자리에 적고 그때부터 접수합니다"* 라고 적어 두었다. 여기에 주소를 채우면서
그 문장을 안 고치면 **약관과 앱이 서로 다른 말을 한다.** 둘은 한 세트로 고친다.

비었을 때 그 자리를 **빈칸으로 두지 않는다** — 지금 할 수 있는 것(대장님 · 탈퇴 · 데이터 초기화)을
적는다. 관문이 그 문장이 있는지 본다.

### ② 진단 정보에 개인정보를 담지 않는다
학생이 **복사해서 남에게 보내는 값**이다. 이름·학교·학과·성적이 한 줄이라도 섞이면 그 순간
개인정보가 새는 경로가 된다. 관문(`verify-settings.js` '고객센터' 절)이 픽스처의
`김한장`·`한국외국어대학교`·`영어학과` 로 **실제로 재서** 막는다.

### ③ 갈래 칩은 `.filter-row` 를 쓰지 않는다 — 접는다
`.filter-row` 는 가로 스크롤인데, 안쪽 화면은 뒤로 쓸기 때문에 `#app.on-sub-screen` 에
`touch-action: pan-y` 가 걸려 있어 **손가락으로 옆으로 밀 수가 없다**(도우미 칩 줄에서 이미 겪은
문제다 — `style.css` 맨 끝 주석). 갈래가 일곱이라 한 줄에 안 들어가므로 접는 쪽이 맞다.
⚠️ 탐색 화면의 '일렬로'(2026-09-12 개발자 지시)와 어긋나지 않는다. 거기는 칩이 다섯이고
안쪽 화면이 아니라 손으로 밀 수 있다.

### ④ FAQ 는 **열 때마다** 검색어·갈래를 되돌린다 (`faqReset`)
틀(검색창·칩)은 한 번만 그린다 — 글자를 칠 때마다 다시 그리면 커서가 튄다. 그런데 그 때문에
`dataset.filled` 로 일찍 돌아가면서 **상태가 남았다.** 실측: 없는 낱말을 찾아 빈 화면을 본 뒤
설정으로 나갔다 '자주 묻는 질문'을 다시 누르면 **또 빈 화면**이 떴다. 목록에서 다시 들어오는
것은 "처음부터 보겠다"는 뜻이다.

### ⑤ 검색은 질문뿐 아니라 **답도** 본다 — 그래서 답에도 표시를 남긴다
'기초생활수급'은 질문에 없고 답에만 있다. 질문만 보면 그 학생은 영영 못 찾는다.
다만 답에서만 걸리면 목록에서 **왜 나왔는지가 안 보이므로**, 펼쳤을 때 걸린 자리가 보이게
표시를 남긴다. 🔴 답은 이미 HTML(`<strong>`)이라 통째로 바꾸면 태그가 깨진다 —
`faqMarkHtml` 이 태그와 글자를 갈라 **글자 조각에만** 넣는다.
🔴 표시는 반드시 `esc()` **뒤에** 넣는다(먼저 넣으면 화면에 `<mark>` 가 글자로 뜬다).

### ⑥ 판 번호는 `APP_VERSION` 한 곳이다
MY 아래 줄과 고객센터의 진단 정보가 같은 값을 써야 한다. 두 곳에 적어 두면 한쪽만 고쳐져
**학생이 알려 준 판 번호가 실제와 달라진다.** `index.html` 에는 이제 숫자가 없다(`#my-version`).

## 4. 곁다리로 고친 것 — 지우기 ✕ 가 둘이었다

`type="search"` 는 브라우저가 지우기 ✕ 를 제 손으로 하나 더 그린다. 우리는 이미 `.search-clear`
를 두고 있어서 글자를 치면 ✕ 가 나란히 둘 떴다. **자주 묻는 질문에서 눈으로 발견했지만
탐색 화면도 처음부터 같았다**(내가 만든 것이 아니다). 한 곳에서 같이 껐다.
⚠️ `appearance: none` 만으로는 안 사라진다 — 계산값이 `none` 인데도 그려졌다(실측). `display: none` 까지.

## 5. 관문

`verify/verify-settings.js` 의 두 절 — 「고객센터 (2026-09-13 신설)」·「자주 묻는 질문 — 검색 · 갈래」.
🔴 **되돌려 빨간불을 확인했다**(red-green): 진단 정보에 이름 섞기 · 답 표시 빼기 · ✕ 끄기 빼기 ·
검색칸 안 비우기 · TOP 에 없는 질문 넣기 — 다섯 다 정확히 그 항목이 빨간불이 났다.

⚠️ 질문을 더하거나 뺄 때는 `FAQ 가 열여덟 줄이다` 의 숫자도 같이 고친다.
