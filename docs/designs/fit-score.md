# 적합도 재설계 — 자격 요건 기반 퍼센트 (2026-08-24 설계)

> 개발자와 합의 완료. 구현 전 설계 문서다. **구현 계획은 별도.**
> 이 문서를 읽는 사람은 코드를 몰라도 된다 — 무엇을 왜 바꾸는지만 적었다.

## 왜 바꾸나 — 지금 적합도는 아무것도 재고 있지 않다

개발자 지적: *"학생이 적합도를 보고 들어갔는데 자격요건을 보니 신청을 못 하는
장학금이면 피로감이 쌓여서 결국 우리 앱을 안 쓰게 된다."*

실측으로 확인했다. 외대 3학년·평점 3.5·소득 5구간 학생에게 보이는 27건의 적합도는

```
57% : 13건
54% : 14건
```

**딱 두 값**이다. 27건 전부 판정 상태가 `selective`(자격을 확실히 못 가림)이고,
57과 54의 차이도 학생과 무관한 데이터 유무에서 온다. **적합도순 정렬 = 사실상 무작위**다.

원인은 자격 조건이 구조화돼 있지 않아서다:

| 구조화된 자격 조건 | 보유 공고 |
|---|---|
| `schoolOnly` (학교 한정 — 자격이 아니라 필터) | 182건 |
| `flagsAny` (특별자격) | 5건 |
| `maxBracket` (소득구간) | 3건 |
| `minGpa` (성적) | **1건** |
| **학교한정을 뺀 진짜 자격 조건** | **9 / 196건** |

`fitScore`는 `62 - 8(selective) + 3(schoolOnly)` = 57에서 거의 움직이지 않는다.
학생이 보는 퍼센트는 **근거가 없는데 정밀해 보이는 숫자**다.

## 만드는 것 셋

순서대로 의존한다.

### ① 요건 파서 — `parse-requirements.js` (신설)

이미 깨끗해진 자격 줄(`section-head.js` 작업 결과)에서 구조를 뽑는다. **규칙만 쓴다 — 비용 0.**

```
"직전학기 평점평균 3.0 이상"        → { gpa: {min: 3.0, unit: '4.5만점'}, 확신: 높음 }
"학자금지원구간 9구간 이내"          → { bracket: {max: 9}, 확신: 높음 }
"휴학생, 졸업생, 자퇴생" (제외 칸)   → { status: {not: [휴학, 졸업, 자퇴]}, 확신: 높음 }
"경제적 지원이 필요한 학생"          → 판정 불가 (확신 없음)
```

**핵심은 확신도를 함께 내는 것이다.** 확신이 낮으면 판정에 쓰지 않는다.
이것이 0% 정확도의 근거다.

**브라우저·Node 겸용**으로 만든다(`section-head.js`·`match-engine.js`와 같은 방식).
화면·감사·검사가 **같은 파일**을 쓴다 — 베끼면 갈라진다.

### ② 프로필 확장

실측 해금률(자격 줄 382개 중 그 항목이 필요한 비율)이 근거다.

| 추가 항목 | 해금 | 형태 |
|---|---|---|
| **학적상태** | **37%** | 재학 / 휴학 / **복학예정** / 초과학기 / 졸업유예 / 수료 |
| 직전학기 이수학점 | 9% | 숫자 1칸 |
| 가계·특별자격 3종 추가 | 8% | 기존 5종에 **한부모 · 북한이탈(새터민) · 다문화** 추가 |
| 거주지 | 7% | **본인 + 부모** 시·도 (아래 주의) |
| 국적 | 5% | 대한민국 / 외국인 유학생 / 복수국적·영주권 |
| 생년 | 2% | 4자리 — `만 39세 이하`·`만학도` 판정용 |

**🔴 거주지는 본인만 물으면 안 된다** — 지역 장학금은 전부 `부 또는 모가 1년 이상 거주`를
요구한다(정읍시민·세종이도·충북인재). 본인과 부모를 따로 받는다.

**🔴 학적상태에 `복학예정`을 반드시 별도 선택지로 둔다** — 자격에 `복학예정자`를 명시한 공고가
**14건**이다. `재학/휴학` 둘로만 받으면 복학예정자가 휴학생으로 분류돼 오탐 0%가 난다.

**묻지 않기로 한 것** (실측 후 제외): 이수학기수 3%(학적상태로 커버) · 타장학 수혜 1% ·
학자금대출 1% · 기숙사 0%. 온보딩이 길어지면 이탈하므로 해금률이 낮은 것은 넣지 않는다.

**대학 소재지는 묻지 않는다** — `서울 소재 대학` 요건은 학교명에서 나온다.

### ③ 적합도 재설계 — `match-engine.js`

**퍼센트는 카드에서 바로 설명돼야 한다.** 숫자만 있으면 지금 문제가 그대로 반복된다.

```
요건 6개 · 충족 4 · 확인 필요 2  →  67%
```

| 상황 | 적합도 | 근거 |
|---|---|---|
| **확신 있는 미달 1개 이상** | **0%** | 자격이 안 되니 0. 목록 맨 아래 + 미달 사유 빨강 |
| 요건을 1개 이상 읽음 | `충족 ÷ 전체 × 100` (최저 **15%**) | 확인 필요는 분모에만 = 감점(결정 2) |
| **제외 조항에 걸림** | **0%** | '휴학생 제외'인데 학생이 휴학이면 미달과 같다 |
| 요건을 하나도 못 읽음 | **35%** + '자격 미확인' 배지 | 읽어낸 공고보다 낮게 깔아 오클릭을 줄인다 |

- **🔴 분모 '전체'는 화면에 나가는 자격 줄 전부다** — 파싱에 성공한 줄만이 아니다.
  파싱 못 한 줄이 분모에만 들어가야 '못 읽은 요건 = 감점'(결정 2)이 성립한다.
  예: 자격 줄 6개 중 파서가 4개를 읽고 학생이 그 4개를 다 충족 → `4 ÷ 6` = **67%**.
- **미확인 35%가 붙는 공고는 53건**이다(196건 중 자격 줄이 있는 건 143건).
  0%(미달 확정)와 구분돼야 해서 35%로 뒀다.
- **두 상수(15 · 35)는 임의값이다.** 한 곳에 상수로 빼 두고 실제 분포를 보고 조정한다.
- **가중치는 두지 않는다.** 성적이 거주지보다 중요하다고 볼 근거가 없고, 가중치를 넣는 순간
  "왜 67%인가"에 답할 수 없게 된다.

## 0%를 내는 조건 — 여덟 가지를 모두 만족할 때만

0%는 **학생에게서 장학금을 뺏는 판정**이라 틀리면 가장 비싸다.
하나라도 어긋나면 그 요건은 **'확인 필요'**로 떨어진다. **의심스러우면 0%를 내지 않는다.**

1. **요건 줄이 '자격' 칸에서 왔다** — 선발기준·우대·부연에서 온 줄로는 0%를 내지 않는다
2. **파싱 확신이 높다** — 숫자·단위·비교어가 명확한 경우만 (`3.0 이상` ✅ / `성적이 우수한` ❌)
3. **학생 프로필에 그 값이 실제로 있다** — 안 채웠으면 '확인 필요'지 미달이 아니다
4. **비교가 뒤집힐 여지가 없다** — 괄호 안 예외(`단, 신입생은 미적용`)가 붙어 있으면 안 낸다
   (신·편입생 예외 조항이 붙은 공고가 **5건** 있다)
5. **🔴 선택지(OR) 구조를 잃지 않았다** — `아래 세 가지 조건 중 하나를 만족하는 자` 아래 항목은
   **선택지**지 필수가 아니다. 하나만 만족해도 충족으로 친다.
   ⚠️ **2026-08-24 현재 실제로 깨져 있다** — 그 안내 줄이 '가리키는 줄'로 제거되면서 선택지가
   필수처럼 렌더링된다(`auto-jukr145233439artclviewdo`에서 실증). 같이 고쳐야 한다.
6. **성적 단위가 같다** — 데이터에 `평점 3.0/4.5` · `백분위 70점` · `B학점 이상` 세 가지가 섞여 있다.
   백분위 70점을 평점 70으로 읽으면 **거의 모든 학생이 0%**가 된다. 단위 미확정이면 판정하지 않는다.
7. **학적상태 매핑이 모호하지 않다** — `복학예정`을 `휴학`으로 뭉개지 않는다(위 14건)
8. **한 공고에 장학금이 여러 종이 아니다** — `(한국가스안전공사장학금)…` `(특기장학금)…`처럼
   묶인 공고(현재 1건)는 하나에 미달해도 다른 것에 지원할 수 있으므로 0% 대상에서 뺀다

**0% 판정에는 반드시 사유를 함께 낸다** — `소득 5구간 · 3구간 이하 필요`처럼.
**사유를 못 쓰면 0%도 못 낸다**(설명할 수 없는 0%는 파싱이 틀렸다는 뜻이다).

## 검증

- **순수 모듈** — 파서는 인터넷·API 없이 `node`로 입출력을 검사할 수 있게 만든다.
- **0% 전수 리포트** — 0% 판정 공고를 사유와 함께 전부 출력한다. 원문과 대조해 오탐을 찾고,
  **오탐이 1건이라도 나오면 그 규칙의 확신 등급을 낮춘다.**
- **전후 비교** — 이 영역의 작업 방식대로 파서 수정 전후로 숫자를 비교한다
  (구조화된 요건 수 · 0% 건수 · 미확인 건수).
- **회귀 검사** — 위 1~8 각각을 `verify/test-collector.mjs`에 넣는다.
  특히 **5번은 2026-08-24에 생긴 문제**라 되돌아가지 않게 못박는다.
- **브라우저 확인 필수** — `match-engine`은 Node에선 require, 브라우저에선 전역이다.
  전역 목록을 빠뜨리면 Node 검사는 통과하는데 앱이 첫 카드에서 죽는다(실제로 겪었다).
