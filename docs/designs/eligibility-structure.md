## 무엇이 문제인가

개발자 지시: "자격 요건 매칭 그거 진짜 사람이 한 것처럼 완벽하게 띄우고 싶다."

증상을 물으니 **네 가지 전부**라고 답했다.

1. 빈칸 — "지원 자격을 아직 읽지 못했어요"
2. 잘린 조각 · 엉뚱한 줄 — `마일리지 산정기간`, `성적 인`
3. 뜻이 뒤집힌 줄
4. 모양은 맞는데 사람 글 같지 않음

네 증상은 하나의 뿌리에서 나온다: **낱말 규칙으로 문장의 뜻을 판정하려 했다.**
`match-engine.js requirementLines()`는 잡음 낱말 9종을 블랙리스트로 버린다.
규칙은 낱말을 보지 문장을 못 읽고, **표는 더더욱 못 읽는다.**
그래서 규칙을 더해도 "사람처럼"에 도달하지 않는다 — 개발자가 세 번 지적했고
세 번 다 규칙을 더한 이유가 이것이다(CLAUDE.md '자격 잡음' 절).

### 결정적 증거 — 동국대 종단추천장학

원문(`collector/extracted/notices-text.json`)의 실제 구조는 표다:

```
신청대상
  공통          대한불교조계종 스님 (학부 정규학기 재학생)
  재학생(계속)   2026-1학기 기수혜자  +  2026-2학기 재학·복학예정자
  재학생(신규)   교육원의 장학추천 가능자
  성적기준       직전학기 평점평균 3.0/4.5, 15학점 이상
```

**공통 1개 + 둘 중 하나 + 성적.** 앱이 그리는 화면:

```
· 대한불교조계종 스님 (학부 정규학기 재학생)
· 2026-1학기 종단추천장학 기수혜자
· 2026-2학기 재학 및 복학예정자 (정규학기까지)
· 대한불교조계종 교육원의 장학추천 가능자
· 직전학기 평점평균 3.0/4.5, 취득학점 15학점 이상 취득자
```

다섯 줄이 전부 나란하다. 학생은 "기수혜자면서 **동시에** 신규 추천도 받아야 한다"로 읽는다.
실제로는 **둘 중 하나**다. 신규 지원자가 이 카드를 보고 포기한다.

**문장은 한 글자도 안 틀렸는데 뜻이 틀렸다.** 원칙 8-1이 지키려던 정직이,
원칙 8-1을 지킨 상태에서 깨진 것이다. 이 한 건이 이 설계의 근거 전부다.

실측:

```
등록 공고 169건 원문 전체를 통째로 넘길 때 (1회)
  정리한 것    소넷    620원   오퍼스   3,100원
  원문 그대로  소넷  2,229원   오퍼스  11,144원
```

**2천 원짜리 문제를 최적화하느라 AI 대상 50건 중 25건을 버리고 있었다.**

양식 스키마화(`schematize-forms.mjs`)는 PDF를 통째로 보내니 그 절약이 옳았다.
자격 요건은 **글자만 보내는데** 같은 규칙을 물려받았다.
→ 자격 경로는 **비용이 아니라 정확도로** 설계한다.

## 채택안 상세

### 1. AI에게 구조를 물어본다 (`collector/eligibility-ai.mjs`)

출력 스키마를 줄 번호 배열 → **구조**로 바꾼다:

```jsonc
{
  "common":   [12, 13],          // 모두 만족해야 하는 요건
  "either": [                    // 이 갈래 중 하나만 만족하면 됨
    { "label": 14, "lines": [15, 16] },   // 14 = "재학생(계속장학생)" 줄
    { "label": 17, "lines": [18] }        // 17 = "재학생(신규자)" 줄
  ],
  "grade":    [20],              // 성적·학점 조건
  "exclude":  [24],              // 제외 대상
  "priority": [26, 27],          // 우선 선발 기준
  "none":     false
}
```

**갈래에는 반드시 이름이 붙는다** (2026-08-23 개발자 지적). 갈래를 갈라 놓고
"이 갈래가 누구 것인지"를 안 적으면 학생이 어느 쪽을 봐야 할지 모른다.
학생은 자기가 계속장학생인지 신규자인지 알고 있으므로, 그 이름이 화면에 있어야
자기 갈래만 읽는다. **`label`도 줄 번호다** — 앱이 원문에서 꺼내므로 지어낼 자리가 없다.
원문에 갈래 이름이 없으면 `label: null`로 두고 앱이 '첫째 · 둘째'로만 가른다.

**여전히 번호만 받는다.** 화면 글자는 앱이 제 원문에서 그 번호로 꺼낸다.
`공통`·`둘 중 하나`·`제외` 같은 짜임말은 **앱이 붙인다**(모델이 아니다).
→ 관찰된 사례(종단추천)는 **문장을 한 글자도 다시 쓰지 않고** 해결된다.

#### 🔴 축약 금지 — 기관명은 반드시 풀네임 (2026-08-23 개발자 지시)

**기관·재단·종단·시험·제도의 이름을 줄이면 안 된다.** 줄이는 순간 학생이
남의 공고를 자기 것으로 읽는다:

| 원문 | 줄이면 | 사라지는 것 |
|---|---|---|
| 대한불교조계종 스님 | 스님 | 어느 종단인지 — 다른 소속 스님이 자기 얘긴 줄 안다 |
| 2026-1학기 **종단추천장학** 기수혜자 | 기수혜자 | 무슨 장학금 기수혜자인지 |
| **대한불교조계종** 교육원의 장학추천 가능자 | 교육원의 장학추천 가능자 | 어느 교육원인지 |

이 규칙이 생긴 경위: 설계 세션에서 **내가(Claude가) 비교표를 그리며 이 셋을 전부 줄였다.**
표 칸에 맞추려던 것인데, 그게 바로 이 설계가 막으려는 실패다.
**"보기 좋게 다듬는 것"이 정보를 죽이는 과정 그 자체**라는 증거로 남긴다.

→ 원문 지지 검사에 **고유명사 보존 검사**를 넣는다: 원문 줄에 있던 고유명사
(따옴표·대괄호 안, `○○재단`·`○○종`·`○○원`·`○○장학` 꼴, 시험·자격증 이름)가
다듬은 문장에 **하나도 빠짐없이** 남아 있어야 한다. 하나라도 빠지면 원문 그대로로 되돌린다.
길이를 줄이는 방향의 다듬기는 이 검사를 사실상 통과하지 못한다 — 의도한 결과다.

**다듬기 갈래(예외 승인분)** — 위로 안 되는 경우에만:
- 모델이 `rewrite: { "12": "다듬은 문장" }`을 함께 낼 수 있다
- 화면에 나가려면 **원문 지지 검사**를 통과해야 한다 —
  다듬은 문장의 내용어(숫자·고유명사·자격 낱말)가 지목한 원문 줄에 전부 있어야 한다
- 통과 못 하면 원문 그대로로 되돌린다. 지어냄이 조용히 통과할 자리가 없다

**🔴 이 갈래는 기존 회귀 검사와 정면으로 부딪힌다.**
`verify/test-collector.mjs`에 이런 항목이 있다:

```js
const made = v({ none: false, lines: [1], text: '최대 987654원 지급' });
eq('  모델이 보낸 글자는 결과에 섞이지 않는다',
   JSON.stringify(made.lines).includes('987654'), false);
```

주석에는 **"이것이 이 파일의 존재 이유"** 라고 적혀 있다. 다듬기 갈래는 이 단언을 깬다.
→ 검사를 **지우지 말고 갈라 쓴다**: 다듬기가 꺼져 있을 때는 지금 단언 그대로,
켜져 있을 때는 '원문 지지 검사를 통과한 것만 통과'로 바꾼 단언을 **하나 더** 둔다.
지금 검사를 지우면 8/20에 왜 그걸 만들었는지가 사라진다.
아래 '남은 질문'에서 다듬기를 아예 안 쓰는 쪽이 나을 수 있다고 적은 이유이기도 하다.

### 2. 애매하면 보수적으로 — 갈래 판정의 기본값

`common` 과 `either` 를 헷갈리면 방향에 따라 손해가 다르다:

- 택일인데 **공통**으로 붙임 → 자격 있는 학생이 포기 (기회 손실)
- 공통인데 **택일**로 붙임 → **자격 없는 학생이 서류 떼고 신청** (최악)

→ **모델이 확신하지 못하면 `common`으로 넣는다.** 프롬프트에 명시하고 회귀로 고정한다.
`requirementMatch()`가 "조금이라도 애매하면 null"인 것과 같은 규칙이다.

### 3. 대상을 넓힌다 (비용 전제가 틀렸으므로)

- `minBodyChars: 200` → **20** 또는 제거. AI 대상 25 → 50건.
- `maxApiCallsPerRun: 3` → 전수 1회용 `--all` 모드 신설. 이후 실행은 신규분만.
- **AI 입력에는 보일러플레이트 제거를 쓰지 않는다** — 표 구조가 stripper에 뭉개진다.
  원문 그대로 보내도 전수 2,229원이다.
- 대상을 '빈칸만'이 아니라 **169건 전수**로 한다 — 구조 소실은 이미 뜨는 125건에 있다.

### 4. 앱이 구조를 그린다 (`match-engine.js` + `app.js`)

- `requirementLines()`가 평평한 배열 대신 구조를 낸다. **기존 호출부는 평평한 형태도
  계속 받게 둔다**(구조가 없는 항목·구버전 데이터). 알림·챗봇·감사가 같은 파일을 쓰므로
  화면과 알림이 갈라지지 않는다.
- '둘 중 하나' 갈래는 시각적으로 갈라 그리고 **갈래 이름을 머리에 단다**:

```
▸ 모두 해당해야 해요
   · 대한불교조계종 스님 (학부 정규학기 재학생)
   · 직전학기 평점평균 3.0/4.5, 취득학점 15학점 이상 취득자

▸ 아래 둘 중 하나에 해당하면 돼요

   [ 재학생 — 계속장학생 ]
      · 2026-1학기 종단추천장학 기수혜자
      · 2026-2학기 재학 및 복학예정자 (정규학기까지)

   [ 재학생 — 신규자 ]
      · 대한불교조계종 교육원의 장학추천 가능자
```

- **5줄 상한을 구조 단위로 바꾼다.** 지금은 줄 5개에서 잘려 구조가 통째로 날아간다
  (사랑나눔에서 `기초생활수급자/차상위`가 그렇게 잘렸다 — CLAUDE.md 기록).
- `sw.js` CACHE 버전 인상 (앱 코드 변경).

- **채점기에 필터와 같은 규칙을 쓰지 않는다** (CLAUDE.md 규칙 유지 — 그러면 새 유형을 영영 못 본다).
- 화면에 **'AI가 읽음 · 검수 전' 표식**. '자동 등록 · 검수 전' 배지 선례 그대로.
  관리자 화면에서 컨펌하면 뗀다.

### 6. 워크플로 배선

- 수집 로봇 2종에 붙인다. **보강 단계 규칙**대로 `timeout-minutes` + `continue-on-error: true`
  — 무슨 일이 있어도 그날 수집분 저장과 리포트는 나가야 한다(2026-08-04 사고).
- 실패 알림은 `if: failure() || cancelled()` — 시간 초과는 '실패'가 아니라 '취소'라 놓친다.
- `git add` 목록에 `data/registered.json` 포함 확인 (로봇이 고치는 파일은 전부 넣는다 — 이슈 #79).
