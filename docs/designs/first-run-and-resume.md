# 첫 실행 화면 · 이어보기

2026-09-09 · 노션 백로그 **원문 목록 4번** 에 대응한다.
개발자 지시 원문 ①: *"에브리타임·클로즈처럼 첫 실행 화면을 설계한다.
🔴 최초 실행에만 뜬다 — 앱을 쓰던 학생이 잠깐 다른 화면으로 이탈했다가 최근 앱 목록에서
다시 열면 **작업하던 화면 그대로 돌아와야 한다.**"*

개발자 지시 원문 ② (2026-09-09 추가): *"학생이 신청서 혹은 앱 내에서 어떠한 작업을 진행 중,
**장시간 나갔다가 들어온 경우 해당 프로그레스가 저장**되어 있었으면 해."*

두 줄로 줄이면 이렇다:

> **앱을 켜면 '하던 곳'으로 간다. 처음 켠 사람만 '환영'으로 간다.**
> **그리고 시간이 얼마나 지났든, 학생이 친 글자는 안 버린다.**

🔴 그래서 **창(시간)이 정하는 것은 '어디로 가는가'뿐이고, '무엇을 잃는가'가 아니다.**
창 안이면 하던 화면째 돌아가고, 창을 넘기면 홈으로 가되 쓰던 신청서·온보딩은 그대로 남아
홈의 '신청서 마저 쓰기' 줄로 되살아난다. 이 구분을 흐리면 둘 중 하나가 망가진다 —
전부 되살리면 사흘 만에 켠 학생에게 반쯤 쓴 폼이 튀어나오고, 창으로 같이 버리면
증명서 떼러 간 20분 사이에 크레딧을 낸 AI 초안이 사라진다.

**눈으로 보는 시안** — https://claude.ai/code/artifact/2d324103-60bf-4758-a279-bb64efd6abae
「움직임」 쪽에서 앱을 껐다 켜 볼 수 있고(5분 뒤 / 5시간 뒤 / 알림으로 열기),
「화면 여섯 장」 쪽에 부팅부터 창이 지난 뒤까지 있다.
그림의 원본과 고치는 법은 `docs/designs/mockups/first-run/`.

## 1. 착수 전 실측 — 지금은 정확히 반대로 돌아간다

앱을 띄워(포트 8471) 브라우저로 재현한 것이다. 짐작이 아니다.

| 재 본 것 | 지금 결과 | 왜 그런가 |
|---|---|---|
| 프로필이 있는 학생이 앱을 다시 켠다 | **환영 화면이 먼저 그려진다** | `index.html` 에서 `hidden` 이 없는 화면은 `#screen-onboarding` 하나뿐이다. app.js 가 도착해 `showScreen()` 을 부를 때까지 그게 화면이다 |
| ↳ 얼마나 오래 | app.js 를 2.5초 늦추자 **2.5초 내내** | 스크립트가 17개고 전부 `<body>` 끝에서 차례로 실린다 |
| 탐색 탭에서 나갔다 다시 켠다 | **홈** | app.js 마지막 줄이 `if (state.profile) showScreen('home')` — 하던 화면을 아예 안 본다 |
| ↳ 그때 스크롤 | 홈인데 **282px 내려가 있다** | 브라우저가 이전 화면의 스크롤을 되살리는데, `showScreen` 의 `scrollTo(0,0)` 보다 **나중**이라 진다 |
| 신청서를 쓰다 나갔다 온다 | **쓴 것이 통째로 없다** | `formFill`(app.js:1242)·`bulkPrep`(1701)은 메모리 변수다. 답은 `이대로 신청 준비 완료`를 누를 때만 저장된다(1315) |
| 시작 중 오류가 나면 | **환영 화면에 갇힌다** | 화면을 정하는 줄이 app.js 맨 끝이라, 그 앞에서 던지면 아무도 화면을 안 바꾼다 |

즉 **최초 실행에만 떠야 할 화면이 매 실행 떠 있고**, 하던 화면은 매번 버려진다.
백로그의 🔴 가 가리키는 것이 이 둘이다.

🔴 마지막 줄(오류 시 갇힘)은 우연히 드러났다 — 검사용으로 만든 프로필에 칸 하나가 빠져
app.js 가 `Cannot read properties of undefined` 를 던졌는데, 그 학생 화면에 남은 것은
**'시작하기' 버튼**이었다. 눌렀으면 온보딩을 처음부터 다시 했을 것이다.

### 값이 가장 큰 손실은 신청서다

`formFill.ans` 는 화면(시트)의 칸에서 읽어 온다. 그래서 다시 열면 **학생이 쓴 글이 전부
사라진다.** AI 초안(`essay.js`)도 같은 자리에 있다 — 그건 **학생이 크레딧을 낸 것**이다.
잠깐 증명서를 떼러 갔다 온 사이에 돈 주고 받은 초안이 없어지는 것은 단순한 불편이 아니다.

## 2. 화면 세 장

### ① 부팅 화면 — 켤 때마다, 아무 말 없이

배경 `#fefdfc` · 가운데 학사모 + '한대장' · 그 외 아무 글자도 없다.

- 🔴 **여기에 "한 번에 찾고 한 번에 신청하세요"를 넣지 않는다.** 그건 환영 화면의 말이다.
  매 실행 뜨는 자리에 두면 학생은 자기 앱에서 매번 광고를 보게 되고, 그게 백로그 🔴 가
  막는 것이다. 부팅 화면은 **비어 있는 것이 설계**다.
- 배경색은 `manifest.json` 의 `background_color`·`<meta name="theme-color">` 와 **같은 값**이어야
  한다. 안드로이드 설치형은 그 색으로 제 스플래시를 그리므로, 다르면 켤 때 색이 한 번 튄다.

#### 시간 (2026-09-09 개발자 지적으로 정해짐)

개발자 지적: *"방금 앱에 최초 접속했는데 환영 화면이 나타났지만 사용자가 겨우 볼 수 있을 만큼
시간이 짧았어. 아까 시안에서 보여준 것과 같은 시간이 적당했어."*

| 값 | 얼마 | 왜 |
|---|---|---|
| 최소로 보여 주는 시간 | **1,000ms** | 개발자가 써 보고 정한 값(처음엔 750ms 였다) |
| 걷힘(접힘 → 쉼 → 열림) | 260+60+420ms | 2026-09-11 페이드 120ms 에서 바뀜(아래 '걷힘 움직임'). 길면 앱이 느려 보인다 |
| 시한(안전장치) | 6초 | 무슨 일이 있어도 스스로 걷힌다 |

🔴 **바닥값이 없으면 보이는 길이가 '앱 코드가 실리는 데 걸린 시간' 그대로**가 된다.
그래서 기기·회선·캐시에 따라 들쭉날쭉했다 — 캐시가 데워진 폰에서는 깜빡이고 말았다.
지금은 준비가 아무리 빨라도 1초는 떠 있다(실측: 재실행 1,451ms / 1,475ms).
🔴 세는 기준은 **`boot.js` 가 실린 때**다 — 부팅 화면이 그려지는 시점과 가장 가깝다.
⚠️ `performance.now()`(페이지가 열린 시각)로 재지 말 것. 한 번 열어 둔 문서를 다시 쓰는
경우(뒤로가기 캐시·설치형 앱의 재개)에는 그 값이 **이미 커져 있어 기다림이 0이 되고
부팅 화면이 깜빡이고 만다.** 처음에 그렇게 짰다가 되돌렸다.
⚠️ 이 값을 키우면 앱이 그만큼 느려진다. 목적은 기다리게 하는 것이 아니라
**'깜빡였다'가 아니라 '봤다'가 되게** 하는 것이다.
· 관문: `test-collector.mjs` — 시안의 값과 앱의 값이 갈라지면 실패한다.

#### 등장 움직임 (2026-09-09 개발자 지시 — 선조치 후보고)

개발자 지시: *"환영 화면에서 인터랙션이 있었으면 해. 예를 들어 로고나 글자가 애니메이션
형태로 나타난다던가. 하지만 **앱의 신뢰성을 떨어뜨리지 않으면서도 깔끔해야** 해."*

두 조건이 서로 당긴다 — 움직임은 눈에 띌수록 좋고, 신뢰는 조용할수록 얻는다.
그래서 '무엇을 하는가'가 아니라 **'무엇을 안 하는가'** 로 셋을 정했다.

| | 규칙 | 왜 |
|---|---|---|
| ① | **한 번만 나타나고 멈춘다** (로고·글자에 `infinite` 금지) | 1초짜리 화면에서 계속 움직이면 '들어왔다'가 아니라 **'아직도 로딩 중'** 으로 읽힌다. 그게 신뢰를 깎는 자리다 |
| ② | **바닥값(1초)보다 일찍 끝난다** — 로고 0.02+0.44s · 글자 0.16+0.40s → 0.56초에 종료 | 걷히는 순간까지 움직이고 있으면 급해 보인다. **끝나고 남는 정지**가 차분한 인상을 만든다 |
| ③ | **튀지 않는다** — 되튐·회전·번쩍임·글자 하나씩 나타내기 없음. 감속 곡선 하나 | 그런 것이 앱을 장난감처럼 보이게 한다. 여기는 학생이 장학금 정보를 맡기는 첫 화면이다 |

계속 도는 표시(`.boot-spin`)는 **바닥값이 지난 1.2초 뒤에야** 나타난다.
🔴 앱이 제때 오면 화면이 1.12초에 걷히므로 **학생은 이걸 아예 못 본다 — 그게 맞다.**
이게 보인다는 것은 '평소보다 오래 걸린다'는 뜻이고, 그 말이 사실일 때만 해야 한다.
처음부터 띄우면 빠른 기기에서도 매번 '기다리는 화면'이 된다.

🔴 움직임을 줄인 기기에서는 `.boot-spin` 의 `opacity: 1` 을 **같이** 되돌려야 한다 —
등장 애니메이션이 opacity 를 올리므로 `animation: none` 만 쓰면 **영영 안 보인다**
(느린 기기에서 아무 표시도 없는 빈 화면이 된다).

바뀌는 것은 `opacity`·`transform` 뿐이라 레이아웃을 다시 계산하지 않는다(B-3 모션 점검 규칙).

**브라우저 실측(2026-09-09, 첫 그리기 기준)** — 글자가 다 나타난 때 904ms ·
부팅 화면이 사라진 때 1,503ms → **다 나타난 뒤 599ms가 고요하다.** 도는 표시는 끝까지
안 보였다(앱이 제때 왔다). 움직임 줄이기를 켠 기기에서는 등장 없이 바로 보이고
도는 표시는 처음부터 보인다.

· 관문: `test-collector.mjs` '첫 실행 화면' 절 ⑨ — 11항목. 바닥값보다 일찍 끝나는가 ·
  `infinite` 가 없는가 · 도는 표시가 바닥값 뒤인가 · 움직임 줄이기가 opacity 를 되돌리는가 ·
  시안(`Boot.dc.html`)과 앱의 값이 같은가. 다섯 가지로 일부러 망가뜨려 빨간불을 확인했다.

#### 걷힘 움직임 (2026-09-11 개발자 지시 — 카카오웹툰 환영 화면 참고)

개발자가 카카오웹툰 환영 화면 영상(1.18초)을 보여 주며 *"한대장 또한 스플래시에서 다음과 같은
인터랙션이 있었으면 좋겠어"* 라고 했다. 60fps 71프레임을 전부 뽑아 본 것: 로고가 가운데로
**접혀 세로 막대 하나**가 되고(0.3초), 막대에서 한 박자 쉰 뒤(0.2초), **그 막대가 창이 되어**
그 자리에서 홈 화면이 열린다(0.25초). 페이드가 아니라 **로고가 앱이 되는** 움직임이다.

한대장에 옮긴 것 — 걷힘이 페이드(120ms)에서 두 단계(0.68초)로 바뀌었다.

| 단계 | 얼마 | 무엇 |
|---|---|---|
| ① 접힘 `.boot-fold` | 260ms | 글자가 내려앉으며 사라지고, 로고 사각형이 **가로로만** 눌려 12px 막대가 된다. 안의 학사모는 눌리기 전에 먼저 걷는다(찌그러진 그림이 제일 싸 보인다) |
| 쉼 `--boot-hold` | 60ms | 막대에서 한 박자 — 없으면 접힘과 열림이 한 동작으로 뭉개져 '막대가 창이 된다'가 안 보인다. CSS 에 둔다(JS 숫자면 관문 합계에서 빠진다 — 코드 리뷰가 잡았다) |
| ② 열림 `.boot-open` | 420ms | 덮개(#boot)에 막대 자리의 **폭 0 구멍**을 뚫고 화면 전체까지 키운다(`clip-path` polygon evenodd). 구멍이 막대 폭을 넘는 순간 막대가 그대로 창이 된다. 앱 화면은 그 밑에 이미 그려져 있다 |

등장 규칙 ①②③(한 번만 · 바닥값 안 · 튀지 않음)은 그대로다 — 걷힘은 바닥값 **뒤에** 붙는다.

🔴 접힘은 transition 이 아니라 **keyframes 애니메이션**이어야 한다. 등장 애니메이션(`both`)이
쥐고 있던 transform 은 브라우저가 transition 으로 이어 주지 않는다 — 처음에 transition 으로
짰더니 260ms 가 **한 프레임에 툭** 바뀌었다(녹화로 확인).
🔴 막대(.boot-logo)를 열림 단계에서 **따로 흐리게 하지 말 것** — 덮개의 구멍이 막대까지 같이
잘라내므로 놔둬야 '막대가 창이 된다'. 따로 흐리면 구멍이 좁을 때 막대가 먼저 사라져
'막대가 없어졌다가 옆에서 구멍이 난다'로 보인다(실측).
🔴 걷히기 시작하면 **도는 표시를 끈다**(`.boot-fold .boot-spin`). 걷힘이 0.68초라 1.2초를
넘기는데, 그때 표시가 스며 나오면 '앱이 제때 왔는데도 기다리는 표시가 보이는' 모순이 된다
(첫 녹화에서 실제로 보였다).
🔴 열리는 자리는 boot.js 가 로고의 **실제 위치**를 재어 `--boot-hx/--boot-hy` 로 준다 — 로고는
화면 정중앙이 아니다(밑에 글자가 있어 28px 위). 안 재면 막대와 구멍이 어긋난다.
🔴 시간은 CSS(`--boot-fold`·`--boot-hold`·`--boot-open`)에만 있고 boot.js 는 **읽기만** 한다.
움직임 줄이기 기기에서는 CSS 가 셋 다 0 을 주고 접지도 열지도 않는다 — 그냥 사라진다(녹화로 확인).
⚠️ 단위 없는 값은 ms 로 읽는다 — `s` 로 끝나는 것만 초다(`260` 을 초로 읽으면 덮개가 4분 남는다).

참고 영상과 다른 것 하나: 카카오웹툰은 막대 안의 홈 화면이 **작게 시작해 커지며** 열리는데,
한대장은 홈 화면은 제자리에 있고 **덮개의 구멍만 커진다**(앱 화면에 손대지 않으려고 — 홈의
배치·스크롤을 건드리는 순간 이어보기와 부딪힌다). 개발자가 보고 정할 것.

**브라우저 녹화 실측(2026-09-11, 25fps)** — 접힘 6프레임에 걸쳐 글자가 사라지고 사각형이
막대가 됨 · 막대 안에 홈이 비치고 가로띠 → 전체로 열림 · 도는 표시 안 보임 · 콘솔 오류 0.
움직임 줄이기: 접힘 없이 곧바로 사라짐.

· 관문: `test-collector.mjs` '첫 실행 화면' 절 ⑩ — 세 값이 있는가 · 합이 0.8초를 넘지 않는가 ·
  `infinite` 가 없는가 · boot.js 가 시간을 CSS 에서 읽는가(숫자를 안 적는가) · 걷힘이 도는 표시를
  끄는가 · 움직임 줄이기가 셋 다 0 을 주는가 · 시안(`Boot.dc.html`)과 값·스크립트가 같은가.
  네 가지(숫자 박기 · 접힘을 transition 으로 · 도는 표시 끄기 제거 · 시안 값 어긋남)로 일부러
  망가뜨려 빨간불을 확인했다.

### ② 환영 화면 — 처음 켠 사람에게만, 한 번

지금 온보딩 0단계를 그대로 승격한다. 로고 · 태그라인 · 세 줄 약속(매칭 · 서류 · 마감) ·
`시작하기`. 무슨 앱인지 한 화면에서 말하는 구성이라 에브리타임·클로즈가 첫 화면에서
하는 일과 같다. 고칠 것은 하나다:

- **진행 막대를 0단계에서는 감춘다.** 아직 아무것도 안 했는데 1/6 이 차 있으면
  "벌써 뭔가 하고 있다"로 읽힌다.

### ③ 이어보기 — 다시 열면 하던 화면

되살리는 것을 세 겹으로 나눈다. 겹마다 위험이 다르기 때문이다.

| 겹 | 무엇을 | 어떻게 |
|---|---|---|
| 1 | 탭(홈·장학금·신청내역·MY) · 목록↔달력 · 탐색의 검색어와 정렬 · 스크롤 | 그대로 되살린다 |
| 2 | 열려 있던 공고 상세 시트 | 다시 열되 **마감·자격을 그 자리에서 다시 판정한다** |
| 3 | 쓰던 신청서의 답과 AI 초안 | 그대로 되살린다 |

🔴 2겹에서 **판정을 저장했다 그대로 쓰면 안 된다.** 자리를 비운 사이에 마감이 지날 수 있다.
CLAUDE.md 의 `'오늘'을 상수로 굳히지 말 것` 과 같은 함정이다 — 그릴 때마다 `dday`·`evaluate`
로 다시 본다. 마감이 지났으면 숨기지 않고 **"자리를 비운 사이에 마감됐어요"** 라고 말한다.

### 되살리지 않는 것 — 일부러

⚠️ **온보딩은 여기 없다.** 처음(지시 ① 때)에는 '되살리지 않는다'로 적었는데, 지시 ②
(2026-09-09)로 **되살리는 쪽으로 뒤집혔다** — 학교·학년을 다시 치게 만드는 것이 이 앱에서
가장 큰 손실이라서다. 3절 참조. 옛 문장을 되살리지 말 것.

| 무엇 | 왜 |
|---|---|
| 알림으로 열렸을 때(`?sch=`·`?screen=`) | **이어보기를 아예 건너뛴다.** 알림을 눌러 놓고 딴 화면이 뜨면 안 된다 |
| 로그인 복귀 토큰으로 열렸을 때 | 같은 이유. 그 흐름은 `supabase-client.js` 가 이미 제 화면을 정한다 |
| 일괄 신청 준비 목록(`bulkPrep`) | 그새 마감된 것이 섞인다. 다시 열 때 `bulkTargets()` 로 새로 고르는 것이 맞다 |

🔴 알림 건은 **먼저 비켜야지, 나중에 덮으면 안 된다.** `notifyHandleLaunch()` 는 시작 후
1.6초에 도는데(`notify.js:690`), 이어보기가 먼저 그리면 화면이 눈앞에서 두 번 바뀐다.
그래서 주소에 `sch`·`screen` 이나 복귀 토큰이 있으면 **이어보기가 처음부터 손을 뗀다.**

## 3. '잠깐'은 얼마인가

개발자 지시의 낱말이 **"잠깐 이탈"** 이다. 그래서 창을 둔다 — 무한정 되살리면 그건
이어보기가 아니라 앱이 멈춰 있는 것이다.

이 앱에서 가장 흔한 이탈은 **증명서를 떼러 가는 것**이다(정부24·학교 포털). 10~30분이
걸리고, 수업을 듣고 와서 이어 쓰는 경우까지 1~3시간이다. 반대로 **밤을 넘겨 아침에 켜는
것은 '하던 것'이 아니다** — 그때 학생이 보고 싶은 것은 '오늘 뭐 있지'라서 홈이 맞다.

> **4시간.** 그 안이면 하던 화면, 넘으면 홈.
> 단 **쓰던 신청서는 7일 동안 안 버린다** — 자동으로 열어 주지 않을 뿐,
> 홈 맨 위에 `쓰던 신청서가 있어요 · 신청서 마저 쓰기` 한 줄로 되살아난다.
> **쓰다 만 온보딩은 창과 상관없이** 치던 단계에서 잇는다 — 학교·학년을 다시 치게 만드는
> 것이 이 앱에서 가장 큰 손실이라, 사흘 뒤에 돌아와도 그 자리에서 잇는 것이 맞다.

🔴 두 숫자는 **뜻이 다르다.** `RESUME_WINDOW_MS`(4시간)는 '어디로 가는가'이고
`RESUME_KEEP_MS`(7일)는 '언제 버리는가'다. 같은 값으로 합치면 개발자 지시 ②가 깨진다 —
관문이 그 둘이 같아지는 것을 막는다(`test-collector.mjs` '이어보기 판정' 절).
🔴 값은 **상수 한 곳**(`resume.js`)에 둔다. 여러 곳에 흩어 두면 그때부터 못 바꾼다.

### 무엇을 '진행 중인 작업'으로 보나

| 작업 | 언제 적나 | 언제 지우나 |
|---|---|---|
| 신청서 답 · AI 초안 | **치는 동안**(0.7초 멈추면) + 앱이 숨을 때 | '이대로 신청 준비 완료'를 눌렀을 때만 |
| 쓰다 만 온보딩(단계·칸) | 치거나 고를 때마다(0.5초) | 온보딩을 마쳤을 때 |
| 탭 · 스크롤 · 열려 있던 공고 | 화면을 옮길 때 · 앱이 숨을 때 | 시트를 닫으면 시트만 |

🔴 **'만들기'를 누를 때 저장하는 것으로는 늦다.** 학생은 아무것도 누르지 않고 나간다 —
증명서를 떼러 가는 것이 이 앱에서 가장 흔한 이탈이다. 그래서 치는 동안 적는다.
⚠️ 글자마다 적으면 긴 자소서에서 버벅이므로 잠깐 멈췄을 때만 적는다(디바운스).

## 4. 어디에 적는가

`localStorage` 의 **따로 있는 열쇠** `handaejang.resume`.

- 🔴 **`state`(프로필·신청내역)에 섞지 않는다.** 그건 로그인하면 서버로 올라가는 것이고,
  이건 이 기기의 화면 상태일 뿐이다. app.js:2958 이 이미 같은 이유로 같은 선택을 해 뒀다.
- 🔴 여기에는 **학생이 신청서에 쓴 글**이 들어간다. 그래서 `syncSafeProfile()` 이 나르는
  것에 절대 들어가면 안 된다. 이건 말로 지킬 것이 아니라 **검사로 증명한다** —
  `verify-supabase.js` 가 쓰는 방식(가짜 서버를 세워 나가는 요청 본문을 전부 모아 센다)을
  그대로 쓴다.
- **언제 적는가**: 화면을 바꿀 때 · 시트를 열고 닫을 때 · 신청서 답이 바뀔 때(디바운스)
  · 그리고 **앱이 숨을 때(`visibilitychange` 의 `hidden`)**. 마지막이 제일 중요하다.
  🔴 `beforeunload` 를 믿지 말 것 — 휴대폰에서는 안 온다. `hidden` 이 유일하게 믿을 수 있는 신호다.

### 스크롤

`history.scrollRestoration = 'manual'` 로 브라우저의 복원을 끈다. 지금은 브라우저가
**이전 화면의 스크롤을 다른 화면에 붙여** 놓는다(실측 282px). 끈 다음 우리가 화면별로
기억했다 되살린다.

## 6. 관문이 증명할 것

🔴 **숫자를 여기 적지 않는다** — 검사를 더할 때마다 낡는다. 실제 목록은 파일에 있다.

`verify/verify-resume.js` — 브라우저 드라이버(`verify-ui.yml` 이 매 push 마다 돌린다).
파일 머리말에 ①~⑧로 무엇을 지키는지 적어 뒀다. 요약하면:

- 프로필이 있는 채 열면 **어느 시점에도** 환영 화면이 안 보인다(app.js 를 늦춰 재현)
- 탭·스크롤이 하던 대로 돌아오고, 남의 화면 스크롤이 안 붙는다
- 창을 넘기면 홈이지만 쓰던 신청서는 남고, 눌러서 이어 쓰면 친 글이 그대로다
- 앱이 숨는 순간에 장부가 적힌다(휴대폰에서만 쓰는 경로)
- 알림으로 열면 이어보기가 지고 그 공고가 열린다 — **공고 목록이 늦게 와도** 열린다
- 학생이 쓴 글이 서버로 나가는 요청에 한 번도 안 들어간다
- 시작 중 오류가 나도 부팅 화면이 스스로 걷힌다

`verify/test-collector.mjs` — 인터넷 없이 도는 정적·순수 검사('첫 실행 화면'·'이어보기 판정' 두 절).
화면을 안 감춘 것이 없는지, `boot.js` 가 첫 스크립트인지, 창과 보관 기한이 같은 값이 아닌지,
시안과 앱의 부팅 시간이 갈라지지 않았는지, 홈 줄의 문구가 그대로인지 등.

🔴 드라이버는 온보딩 단계 번호·공고 id·포트·브라우저 경로를 박지 않는다.
`verify/onboard-helper.js` 의 `nextUntil`·`assertOwnServer`·`dismissNotify` 를 쓴다.
🔴 **느린 회선처럼 평소엔 안 걸리는 조건은 일부러 만들어 재현한다** — 알림 딥링크가
그래서 새 나갔다(빠른 회선에서는 검사가 아무것도 못 잡았다).

## 7. 🔴 되돌리지 말 것

| 되돌리면 | 이렇게 된다 |
|---|---|
| `#screen-onboarding` 의 `hidden` 을 뺀다 | 재실행 때 환영 화면이 다시 깜빡인다(실측된 원래 증상) |
| `boot.js` 를 인라인 `<script>` 로 옮긴다 | CSP 가 막아 **아무 일도 안 일어난다**. 조용히 실패한다 |
| 부팅 화면 버튼에 `onclick="…"` 을 쓴다 | 같은 CSP 가 **인라인 처리기도** 막는다. 실제로 '다시 시도' 가 죽어 있었다(2026-09-09 확인) — 앱이 안 오는 학생이 거기서 갇힌다 |
| 이어보기 값을 `state` 에 넣는다 | 학생이 신청서에 쓴 글이 서버로 올라간다 |
| `beforeunload` 로 저장한다 | 휴대폰에서 안 불린다 — 이탈한 그 순간의 상태를 못 적는다 |
| 부팅 화면에 태그라인을 넣는다 | 매 실행 광고가 된다. 백로그 🔴 이 막는 것이 그것이다 |
| 저장한 판정을 그대로 다시 그린다 | 자리를 비운 사이 마감된 공고를 '신청 가능'으로 보여 준다 |
| 부팅 화면의 바닥값을 뺀다 | 보이는 길이가 앱이 실리는 시간 그대로가 돼, 캐시가 데워진 폰에서 깜빡인다 |
| 그 바닥값을 `performance.now()` 로 잰다 | 문서를 다시 쓰는 경우(뒤로가기 캐시·설치형 재개) 기다림이 0이 된다 |
| 알림 딥링크에서 공고를 한 번만 찾는다 | 목록이 늦게 오는 폰에서 **매번** 장학금 탭으로 샌다(실측) |
| 부팅 화면의 로고·글자를 계속 움직이게 한다 | '들어왔다'가 아니라 '아직도 로딩 중'으로 읽힌다 — 신뢰를 깎는다 |
| 등장 움직임을 바닥값(1초)보다 길게 만든다 | 걷히는 순간까지 움직여 급해 보인다. 끝나고 남는 정지가 차분함을 만든다 |
| 도는 표시를 처음부터 띄운다 | 빠른 기기에서도 매번 '기다리는 화면'이 된다. 그건 사실이 아니다 |
| 움직임 줄이기에서 `.boot-spin` 의 `opacity: 1` 을 뺀다 | 느린 기기에서 아무 표시도 없는 빈 화면이 된다 |
