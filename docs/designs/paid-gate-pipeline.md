# 유료 관문 흐름 — 앱에 올리기 전에 유료가 읽고, 마지막에 유료가 문서를 검토한다 (2026-11-20 개발자 지시)

> *"그 앱에 등록하기 전에 한 번 유료로 확인을 하고 자격요건 로봇을 없애고 그 대신에 api 유료가 이를 대체 · 6번에서 최종 검토할 때 앱에 있는 문서가 똑같은지 알맞은 문서인지, 신청양식이 맞는지, 내용이 있는 문서인지 내용이 있는 문서면 그 내용이 공고 카드에 다 들어가 있는건지."*
> *"ai 가 사람의 두뇌처럼 딱 공고 원문이랑 첨부파일 등을 읽고 이건 자격 이건 어디 … 아 이렇게 쓰면 너무 부자연스럽네 좀 더 깔끔하게 가볼까 이런식으로"*
> *"두 로봇의 의견이 다르면 두번째 로봇이 그냥 다른 부분을 알아서 수정하게 해서 자동으로 올리면 안되나?"* → 운영 원칙 8-1 변경 승인(「ㅇㅇ 그렇게 해」).
> 앞선 설계: `docs/designs/paid-card-reading.md`(유료 카드 읽기 · 이 문서가 그 2·3절을 바꾼다).

## 0. 왜

- 유료 카드 읽기가 지금은 **등록 뒤에** 돌아, 읽기 전까지 학생은 무료 규칙이 고른 자격(번호가 남고 끊긴 줄)을 본다.
- 두 모델이 **따로** 읽고 **같은 말을 한 줄만** 싣는 방식이라, 실측(11-20 · 읽은 59건) 자격 칸이 실린 것은 **16건**뿐이다(40건 보류).
  원인은 대개 틀림이 아니라 **줄을 다르게 자른 것**(인하 장학사정관제: 한쪽은 괄호 예외까지 한 줄, 한쪽은 괄호 앞에서 끊음 → 둘 다 원문 그대로인데 칸 전체가 빠짐).
- 원문 글자만 허용하니 문장이 부자연스럽다 — 개발자는 사람이 읽고 정리한 카드를 원한다.
- 마지막에 「앱에 실린 문서가 맞는 문서인가 · 내용이 카드에 다 들어갔나」를 보는 곳이 없다(지금은 `attach-alarm.mjs` 의 「파일 이름은 보이는데 못 받은 첨부」 경보 하나).

## 1. 흐름 — 여섯 단계

```
① 수집               collect.mjs · browser-collect.mjs          (그대로)
② 숨김 등록           auto-register.mjs → registered.json 에 「유료 확인 전」 표시를 달아 등록
③ 원문·첨부 받기      deepfetch --fill · rescue-bodies(진짜 브라우저) · 글자 뽑기·OCR   (그대로 — 숨김 등록분도 대상)
④ 💰 유료 확인 1     card-read.mjs — 읽기(첫째 모델) → 고치기(둘째 모델) → 기계 검사 → 통과하면 학생 화면에
⑤ 첨부 보관           form-pdf.mjs — 신청서 원본 → PDF                (그대로)
⑥ 💰 유료 확인 2     최종 검토 — 문서 다섯 가지 (3절)
```

## 2. ② 숨김 등록 · ④ 유료 확인 1

### 2-1. 숨김 등록

- 자동 등록(`auto: true`)으로 **새로** 들어오는 공고에 `paidGate: "대기"` 를 단다. 저장 자리는 `data/registered.json` 그대로 —
  원문을 받는 로봇들(deepfetch·rescue-bodies·form-pdf)이 이 파일의 공고만 찾아가므로 따로 두면 그 로봇들을 다 고쳐야 한다.
- **보이는가 = `paidGate` 가 없거나, `data/card-read.json` 에 그 공고의 통과 결과가 있다.** card-read 는 지금처럼 `registered.json` 을 고치지 않는다(유료 결과 파일이 곧 '통과 도장').
- 숨기는 판정은 **한 함수**(match-engine) — 앱(`app-live.js`)·서비스워커(`sw.js`)·`what-shows`·푸시 서버(`server/push/worker.js` 는 사본)가 모두 부른다.
  🔴 `card-read.json` 을 못 받은 날에도 숨김은 지켜져야 한다(지금 `applyCardRead` 는 그 파일이 있을 때만 불린다 — 숨김 거르기를 거기에만 두면 파일이 없을 때 숨김분이 보인다).
- 유료 확인을 못 한 공고(잔액 없음·실패·원문 없음)는 **숨긴 채로** 둔다(= 그날 등록 멈춤). 원문이 끝내 없어(`giveUpAfter` 소진) 못 읽는 것은 관리자 「할 일」 컨펌 대기로.
- 이미 보이는 등록 공고(이 변경 전 등록분)는 **숨기지도 유료로 읽지도 않는다**(개발자 결정 11-20 「나」 — *"출시 한 이후부터 ㄱㄱ … 이전까지 쌓인 거는 걍 버리고"*) — 마감이 지나면 저절로 빠진다. 이미 읽어 둔 `card-read.json` 항목은 그대로 둔다.
  그래서 유료 확인 1 의 대상은 **`paidGate` 가 달린 공고만**이다(지시문이 바뀌어 원문 해시가 바뀌어도 옛 등록분을 다시 읽지 않는다). 그 뒤 관리자가 손으로 등록한 공고는 `paidRead`(숨기지 않고 읽기만).
- 🔴 옛 두 읽기(11-20 전에 모델 둘이 따로 읽은 공고)에서 **두 읽기가 갈린 줄**은 빼고 싣지 않는다 — 자격·제외·서류 칸은 11-18 규칙 그대로 무료 길 값
  (개발자 결정 11-20 *"옛 공고는 일단 냅둬"*). 「빼고 올려」는 기계 검사가 잡은 줄에 대한 결정이고, 갈린 줄을 빼면 한쪽만 낸 요건이 통째로 빠진다
  (리뷰 실제: 안산시 반값 등록금의 소득 갈래 일곱 줄 · 틀린 안심). 갈린 줄은 관리자 「할 일」의 접은 칸에 있고, 그 공고들은 마감되면 저절로 빠진다.
- 시작 시각: 이 코드가 기본 브랜치에 나간 뒤 자동 등록되는 공고부터(아직 출시 전이라 출시 시점과 같다고 본다 · 내 판단).
- 🔴 유료가 **사흘 넘게** 꺼져 있거나(스위치·잔액·연속 실패) 한 번도 통과를 못 내면, 숨긴 공고 가운데 사흘 넘게 기다린 것을 무료 길 값으로 올리고 경보 이슈를 연다(`tools/alert-issue.mjs` · 내 권고를 기본값으로 — 개발자가 답하지 않았다). 비상망을 살리는 장치다.
- **통과 = `card-read.json` 에 그 공고 항목이 있다**(칸 일부가 보류여도 — 보류 칸은 지금처럼 무료 길 값). 둘째 모델도 `unreadable` 이거나 모든 칸이 떨어져 항목이 안 생기면 숨긴 채 → 관리자 컨펌 대기(내 판단).
- 🔴 **한 번 보인 공고는 다시 숨기지 않는다**(내 판단) — 재읽기(3절)가 빈 결과를 내도 숨김분의 기존 항목은 지우지 않고 남긴다(`put()` 이 지우는 자리).
- 관리자 컨펌: 「올리기」 = `paidGate` 를 떼어 무료 길 값으로 보인다(`tools/admin-apply.mjs` `edit` · `paidGate` 를 `tools/edit-diff.mjs` 가 받는 칸으로) · 「빼기」 = 지금의 `blockIds`(내 판단).
- 숨김분은 **정식 등록 목록에서만** 빠진다 — 실시간 공고 피드에는 제목+링크 줄로 그대로 나온다(원칙 2: 피드는 컨펌 없이 게재 · 숨김 거르기는 `registeredUrlMatcher` 보다 뒤에 · 내 판단). 통과 뒤 「새 장학금」 알림이 한 번 더 갈 수 있다 — 받아들인다.
- 숨김 함수를 부르는 곳(빠지면 확인 안 된 공고가 나간다): `app-live.js`·`sw.js`·`server/push/worker.js`(사본)·`verify/what-shows.mjs`·`insta/notices.mjs`·`build-search-index.mjs`·`chat.js`·`server/apply/apply-guard.mjs`·`app-my.js`. 관문이 이 목록을 잰다.

### 2-2. 유료 확인 1 — 읽기 → 고치기 → 기계 검사

- **읽기**(첫째 모델 · 지금 `claude-opus-5-5`): 본문 + 첨부 전부를 읽고 칸을 나눈다. 줄마다 `{ text, quote }` —
  `text` 는 학생에게 보일 **다듬은 문장**(사람이 정리한 것처럼 자연스럽게), `quote` 는 그 줄의 근거인 **원문 그대로의 문구**.
- **고치기**(둘째 모델 · 지금 `claude-sonnet-5-5`): 원문과 첫째 결과를 함께 받아 **고친 결과 전체**를 낸다 — 칸이 틀린 줄 옮기기, 빠진 요건 더하기, 숫자·부정 바로잡기, 어색한 문장 다듬기.
  따로 읽어 비교하지 않는다(그래서 줄 자르기 차이로 칸이 통째로 빠지는 일이 없다).
- **기계 검사**(무료 · 돈 0) — 고친 결과의 **모든 줄**에:
  1. `quote` 가 원문에 있다(지금 `inSource` 그대로 · 느슨하게 하지 않는다).
  2. `text` 의 **사실 낱알**이 `quote` 와 같다 — 숫자(학점·평점·금액·인원·백분위·구간), 날짜, 부정·비교 낱말(않·못·아니·없·제외·불가·이상·이하·미만·초과·이내), 기관·학교 이름.
     `text` 에만 있는 사실 낱알이 있으면 떨어진다(지어냄). `quote` 에 있는 부정·비교 낱말이 `text` 에서 빠져도 떨어진다(뜻 뒤집힘).
  3. 마감은 지금 규칙 그대로(근거 문구에 그 월·일 · 연도 · 게시일보다 늦음 · 「연장」 공고는 보류).
- 떨어진 줄만 빼고 싣는다. 단 자격·제외·서류(`STRICT_FIELDS`)는 한 줄이라도 떨어지면 지금처럼 **칸 전체를 싣지 않는다**(요건이 빠진 목록은 '틀린 안심').
  떨어진 줄은 장부 `held` → 관리자 「할 일」.
- 결과 파일(`data/card-read.json`)의 꼴은 그대로 — 칸마다 **다듬은 문장의 배열**(앱·`checkData` 를 안 바꾼다). 근거 문구는 장부에만.
- 두 모델 결과 원본은 장부 `raw` 에 남긴다(규칙 고친 뒤 `--recheck` 로 돈 없이 다시 잰다 · 지금과 같다).
- 앱은 지금처럼 `applyCardRead` 로 얹는다 — 얹은 공고의 자격은 무료 규칙의 줄 고르기를 건너뛴다(= 무료 자격 고르기는 비상망으로만 남는다).

### 2-3. 「자격요건 로봇」

- `rescue-bodies.yml` 은 자격을 판정하지 않는다 — 진짜 브라우저로 본문·첨부를 받아 온다(③). 유료 확인은 페이지를 못 연다. 그래서 **받아 오기는 남기고 이름을 「원문 받기 로봇 (진짜 브라우저)」로 바꾼다**
  (워크플로 `name:` · `deploy-sync.yml` 의 `workflows:` 목록 · 관리자 통제판 · 문서의 이름 — 한 세트로).
- 그 안의 대외활동 자격 고르기(`activity-docs.mjs --apply`)는 이번 범위가 아니다(아래 비목표).

## 3. ⑥ 유료 확인 2 — 최종 검토

신청서 PDF(⑤)가 생긴 뒤, 학생 화면에 떠 있는 정식 등록 공고마다 한 번(문서·카드가 바뀌면 다시). 모델은 첫째 모델 하나. 공고마다 **앱이 실제로 보이는 문서**(첨부 목록 · `data/forms-pdf/` 사본 · 앱 지원문서)와 **카드 내용**(유료 확인 1 을 얹은 값)을 원문과 함께 준다.

| 검사 | 누가 | 무엇을 |
|---|---|---|
| 원본과 같은가 | 기계 | 앱이 보이는 파일의 글자 ↔ 원문에서 받은 원본 글자(같은 첨부의 해시·글자 대조) |
| 이 공고의 문서인가 | 모델 | 문서의 제목·기관·연도·회차가 이 공고와 맞는가(다른 공고·지난해 문서 아님) |
| 신청양식이 맞는가 | 모델 | 「신청서」로 내보이는 문서가 실제로 학생이 채워 내는 양식인가(공고문·안내문·결과 발표가 아님) |
| 내용이 있는 문서인가 | 기계 → 모델 | 기계: 뽑힌 글자 분량(`MIN_BODY` 기준) · 모델: 빈 껍데기·오류 화면·로그인 화면 아님 |
| 내용이 카드에 다 들어갔나 | 모델 | 문서의 자격·제외·금액·마감·신청 방법·서류 가운데 카드에 없는 것 목록(근거 `quote` 와 함께) |

- 🔴 **카드에 빠진 내용은 자동으로 카드에 넣는다**(2026-11-21 개발자 결정 *"빠진 내용은 자동으로 넣고"*) — 근거가 원문에 있고 사실 검사(factsMatch)를 통과한 줄만, 유료 결과 칸(배열)에만(`data/card-read.json` · 무료 값 칸에는 안 넣고 관리자에게).
- 문서 문제(원본과 다름·다른 공고 문서·신청 양식 아님·내용 없음)는 고치지 않고 보고한다 — 문제 목록을 `collector/final-review.json`(관리자용 · 앱은 안 받는다)에 적고 관리자 「할 일」에 띄운다.
  빠진 내용은 다음 유료 확인 1 재읽기의 대상으로 넘긴다(원문 해시를 지우는 식 · 두 번째 기계 검사를 다시 거친다). 문서가 틀렸으면 그 첨부를 앱에서 내리는 것은 사람이 정한다(내 판단 — 문서를 로봇이 지우면 맞는 문서를 잃을 수 있다). 내리는 버튼은 이번에 새로 만들지 않는다 — 있는 `edit`(첨부 칸 고치기)로 한다.
- 같은 문서·카드는 다시 검토하지 않는다(문서 해시 + 카드 해시 장부).

## 4. 운영 원칙 8-1 (바뀜 — 개발자 승인 2026-11-20)

- 전: 「추론 금지 · 원문 발췌 — 신청 방법·서류는 원문 문장을 그대로 발췌」
- 후: **유료 경로는 원문을 읽고 깔끔한 문장으로 다시 쓸 수 있다. 줄마다 원문 근거 문구를 붙이고, 숫자·날짜·부정·비교 낱말·기관 이름이 근거와 같아야 실린다.**
  무료 경로(비상망)는 원문 그대로. 없는 사실을 지어내지 않는 것은 그대로다(지키는 것은 지시문이 아니라 기계 검사).
- `CLAUDE.md` 의 원칙 8-1 줄과 「유료 카드 읽기」 절을 같이 고친다(60KB 천장 — 경위 괄호를 깎아 자리를 낸다).

## 5. 돈

- 실측 공고 1건 유료 확인 1 ≈ 0.10달러(11-18 장부 평균 · 두 번 읽기). 고치기는 읽기보다 출력이 짧지 않다(결과 전체를 다시 낸다) — 비슷하다고 본다.
- 새 등록은 하루 1~6건(10-15~11-17 실측). 이미 보이는 등록분 ≈300건을 다 읽으면 ≈30달러.
- 유료 확인 2 는 공고당 1회 + 문서가 바뀔 때.
- 측정(11-20 · 돈 0 · 장부·저장 기록으로): 지금 두 모델 읽기 평균 0.101달러/건 · 지난 30일 새 등록 154건(11월 속도 ≈110건/30일) · 새 흐름 어림 1건 ≈0.23달러(확인 1 ≈0.13 + 확인 2 ≈0.10) × 다시 읽기 여유 1.5 → **한 달 ≈38~53달러**(새 공고 세 배여도 ≈160달러). 비용은 사용자 수가 아니라 게시판 공고 수로 정해진다.
- 개발자 결정(11-20): 한 달 200달러면 충분하니 **한 달 상한 장치는 두지 않는다**(*"상한 없애고 ㄱㄱ"*). 실행 한 번의 상한(`maxPerRun`·`maxUsdPerRun`)은 예산이 아니라 **폭주 막이**(같은 공고를 되풀이해 읽는 고장)라 남긴다(내 판단 — 새 공고가 하루 몇 건이라 막히지 않는다).

## 6. 비목표

- 대외활동·공모전(`data/activities.json`)의 자격 고르기 — 별도로 정한다.
- 층2(KOSAF) — 섞지 않는다.
- 무료 경로 코드 삭제 — 비상망이라 남긴다.
- 수집 로봇의 시간 예산·순서 — 손대지 않는다(수집 실행 안에 원문 받기·유료 읽기를 넣지 않는다 · 수집 로봇이 시간초과로 하루치를 잃은 일이 세 번 있다).

## 7. 접근 — 고른 것은 가

| | 방식 | 버린/고른 이유 |
|---|---|---|
| 가 | **숨김 등록** — 등록은 하되 유료 통과 전엔 안 보인다 | 고른 것 — 원문 받기 로봇·시간 예산을 그대로 쓴다 |
| 나 | 순서 바꾸기 — 수집 실행 안에서 원문 받기 → 유료 → 등록 | 수집 실행이 시간 예산을 넘긴다 |
| 다 | 등록 대기줄 로봇을 새로 | 원문 받는 코드가 한 벌 더 생긴다(같은 공고를 두 로봇이 두드린다) |
