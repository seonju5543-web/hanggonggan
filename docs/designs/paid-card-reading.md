# 유료 카드 읽기 — 공고 카드의 모든 칸을 AI 가 읽는 본선 (2026-11-15 개발자 지시)

> *"카드에 있는 모든 내용을 다 api 로 읽을 수 있는 유료 경로도 만들어놓자. 이 경로는 정말 사람이 검수한 것 마냥 내용의 오류가 없고 완벽해야해.
> 무료 경로는 나중에 잔액이 부족할 때와 같은 경우를 대비해서 그냥 비상망으로만."* · *"자격은 말그대로 자격이야 ~는 학생 ~는 자 이런식이지 ~고, 이런식으로 끝나진 않아."*
> 시안(표본 6건 · 실제 API): `docs/designs/mockups/paid-card-reading/` — 2026-11-15 "이대로 만들기" 승인.

## 0. 무엇을 바꾸나

지금 카드의 칸(자격·제외·금액·마감·신청 방법·서류)은 칸마다 다른 규칙이 따로 읽는다(무료 길). 그래서 번호(「3)」「가.」)가 남고, 줄이 「~하고,」에서 끊기고,
선발 인원·장학금 종류 이름이 자격 자리에 앉고, 접수 시작일이 마감으로 읽힌다. 유료 길은 **공고 한 건을 통째로** 읽어 칸을 한꺼번에 나눈다.

- **유료 길이 본선** — 읽은 공고는 유료 결과만 싣는다(무료 값을 남기지 않는다 — 남기면 무료 길의 틀린 값이 그대로 보인다 · 시안 1차에서 실제로 그랬다).
- **무료 길은 비상망** — 유료 길이 아직 안 읽었거나(새 공고·잔액 없음) 못 읽은 공고(원문 없음)만 지금처럼 무료 길 값으로 보인다. 무료 길 코드는 지우지 않는다.

## 1. 접근 셋 — 고른 것은 ②

| | 방식 | 버린/고른 이유 |
|---|---|---|
| ① | 원문 줄 번호만 고르게 한다(기존 `eligibility-ai.mjs` 방식을 모든 칸으로) | 지어낼 자리가 없지만 끊긴 줄·깨진 띄어쓰기·번호가 그대로 남는다 — 개발자가 없애 달라는 바로 그것 |
| ② | **다듬기는 허용하고 사실 추가는 기계가 막는다** | 고른 것 — 아래 2·3절 |
| ③ | AI 가 자유롭게 요약 | AI 말투·지어냄이 들어올 자리가 생긴다 — 원칙 8-1 과 정면으로 부딪친다 |

## 2. 읽기 계약 (지시문 = `collector/card-read.mjs` `SYSTEM`)

사실은 원문 그대로. 허용 손질 다섯: ① 끊긴 문장 잇기 ② 띄어쓰기 고치기 ③ 줄머리 번호·기호 떼기 ④ 줄머리 이름표(「신청방법 :」) 떼기
⑤ 자격·제외 줄의 **끝말만** 고쳐 한 줄이 혼자 읽히게(「…취득하고,」→「…취득한 자」). 그 밖의 낱말은 바꾸지 않는다. 없으면 비운다.

칸: `title` · `host` · `eligibility`(사람·명사로 끝남) · `excludes`(누가 못 받는지만) · `priority` · `amount`(숫자가 든 문구) · `deadline {date, quote}` ·
`apply` · `documents`(서류 이름) · `notes` · `multi`(장학금 여러 종 — 공통인 것만) · `unreadable`.

입력은 **게시판 본문 + 첨부 글자**(공고문 한글·PDF·포스터 OCR). 본문만 주면 표본 6건 중 3건이 「읽을 내용 없음」이었다.

🔴 원칙 8-1(추론 금지·원문 발췌)은 그대로다 — 바뀐 것은 '글자를 한 자도 손대지 않는다'에서 '사실은 그대로 · 손질 다섯만'으로다. 손질이 사실을 바꾸지 못하게 3절이 막는다.

## 3. 싣기 전 관문 셋 (전부 통과한 줄만 화면에 나간다)

1. **기계 대조**(`verify` · 무료) — 줄의 글자(공백·줄바꿈 무시)가 원문에 있어야 한다. 떨어진 두 조각을 이은 것(포스터)은 두 조각이 다 원문에 있을 때만.
   끝말 고침은 끝말을 뗀 줄기가 원문에 있고, 원문에서 그 뒤가 잇는 말(하고·이며·으로…)이며 부정(않·못·아니·없)이 뒤따르지 않을 때만.
   마감은 근거 문구가 원문에 있고 그 문구에 그 월·일이 있어야 한다.
2. **두 번 읽기 일치**(`agree`) — 서로 다른 모델 둘이 따로 읽는다(첫째 = `claude-opus-5-5` · 둘째 = `claude-sonnet-5-5`). 한쪽에만 있는 줄·칸이 갈린 줄은 싣지 않고
   장부(`collector/card-read-ledger.json`)의 `held` 에 남긴다(→ 관리자 「할 일」은 다음 조각).
3. **보류 규칙** — 「연장」 공고(제목·첨부 이름)는 마감을 싣지 않는다(받아 두지 못한 연장 공고문이 진짜 마감을 갖고 있을 수 있다 · hy재단).
   둘 다 `unreadable` 이면 아무것도 안 싣는다(무료 길 그대로).

⚠️ 이것은 '오류 0 보장'이 아니다 — **틀릴 수 있는 것을 싣지 않는** 구조다. 품질은 사람이 정답을 적은 표본으로 재면서 지시문을 다듬는다(다음 조각 · 표본 6건으로만 다듬은 상태).

## 4. 저장 · 앱

- **결과 파일 `data/card-read.json`**(앱이 받는다) — `{ items: { <공고 id>: { title, host, eligibility, excludes, priority, amount, head, deadline, apply, documents, notes, multi, hash, readAt } } }`.
  🔴 `registered.json` 을 고치지 않는다 — 자동 병합에서 뺀 파일이고(충돌), 무료 길 값을 덮어쓰면 비상망이 사라진다. 얹는 것은 앱이 한다.
- **장부 `collector/card-read-ledger.json`**(로봇만) — 공고마다 원문 해시·읽은 날·쓴 돈·`held`·`dropped`·실패 횟수. 원문 해시가 같으면 다시 읽지 않는다(같은 공고에 돈을 두 번 쓰지 않는다).
- **앱** — `applyCardRead(sch, cr)` 한 곳이 공고에 유료 결과를 얹는다(`sch.cardRead`). 판정·화면은 `sch.cardRead` 가 있으면 **무료 길의 거르기(`requirementLines` 의 잡음 규칙)를 건너뛰고**
  유료 줄을 그대로 쓴다 — 줄마다 ✓·✕ 는 엔진(`lineVerdict`)이 그대로 판정한다. 맨 위 금액은 금액 문구에서 숫자만(`wonIn`).

## 5. 돈

- 실측(2026-11-15 · 표본 6건): 첫째 읽기 0.052달러 · 둘째 읽기 0.019달러 · 합 약 0.07달러/건. 전체 647건 한 번 약 46달러.
- 스위치 둘: `collector/card-read-config.json` `enabled` + 환경 변수 `CARD_READ_ENABLE=1`(워크플로만 준다). 한 실행의 상한 `maxPerRun`·`maxUsdPerRun` — 넘으면 멈추고 리포트.
- 가짜 응답 `CARD_READ_FAKE=<파일>` 로 관문을 돈 없이 돌린다(`eligibility-ai.mjs` 의 `ELIG_AI_FAKE` 와 같은 방식).
