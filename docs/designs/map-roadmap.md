# 지도 로드맵 — 학교 은어 · 주변 장소 리뷰 · 커뮤니티 (설계)

> 2026-10-10 · 유은서(CTO) · 팀 업무 분장 프론트 16번
> 지시: "지도 로드맵 API 삽입: 학교 은어, 주변 술집/과팅 장소/카페 리뷰 및 커뮤니티 개설"
> 상태: **설계까지.** 지도 API 열쇠 발급(개발자 몫)과 아래 🔴 결정 3개가 있어야 만든다.
> 2026-11-22 추가: **신입생 지도 시안**(7절 · `docs/designs/mockups/campus-map/index.html`) — 개발자 결정 대기.

## 1. 무엇을 만드나

학교를 고르면 그 학교 주변 지도가 뜨고, 그 위에 세 겹이 올라간다.

| 겹 | 내용 | 데이터 출처 |
|---|---|---|
| 장소 | 카페 · 술집 · 과팅 장소 · 공부 장소 | 지도 API의 장소 검색(가게 이름·위치·영업시간) |
| 리뷰 | 우리 학생이 쓴 한 줄 평 + 별점 | **우리 장부**(Supabase `place_reviews`) |
| 학교 은어 | "중도 = 중앙도서관" 같은 학교 말 사전 + 건물 위치 핀 | 학생이 등록 → 추천 수로 정렬 |

커뮤니티는 리뷰·은어에 댓글이 붙는 형태로 시작한다(게시판을 따로 크게 만들지 않는다).
과팅 앱(백엔드 6·7번)이 같은 장소 데이터를 쓴다.

## 2. 지도 API 고르기

| | 카카오맵 | 네이버 지도 | 구글 지도 |
|---|---|---|---|
| 국내 가게 정보 | 좋음 | 좋음 | 부족 |
| 무료 한도 | 넉넉함(일 30만 회 수준) | 월 사용량 기준 무료 구간 | 월 $200 크레딧 |
| 장소 검색 API | 있음(키워드·카테고리) | 있음 | 있음 |

**권장: 카카오맵.** 대학생 사용성·무료 한도·장소 카테고리(카페 CE7, 음식점 FD6 등)가 맞는다.

## 3. 🔴 보안 설정과 부딪히는 점 — 결정 필요

앱은 **우리 파일 밖의 스크립트를 실행하지 않는다**(index.html CSP `script-src 'self'`).
수집한 공고에 나쁜 코드가 섞여도 실행되지 않게 하는 핵심 장치다(CLAUDE.md "SDK를 쓰지 않는다" 결정과 같은 이유).
카카오 지도는 카카오 서버의 스크립트를 불러와야 그려진다. 길은 셋이다.

| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| A | 지도 화면만 **별도 페이지**(`map.html`)로 분리하고 그 페이지에만 카카오 허용 | 앱 본체 방어선 유지 | 화면 전환이 페이지 이동 |
| B | 앱 전체 CSP에 `dapi.kakao.com` 허용 | 구현 간단 | 방어선이 카카오 한 곳만큼 넓어짐 |
| C | 지도 그림 없이 **목록 + "지도에서 보기" 링크**(카카오맵 앱으로 이동) | 외부 스크립트 0, 오늘 바로 가능 | 지도가 앱 안에 안 보임 |

**권장: C로 먼저 시작 → 반응을 보고 A.** C는 장소 검색만 서버(Cloudflare Worker)에서 하고 결과를 목록으로 보여 준다.
열쇠도 서버에만 두므로 노출되지 않는다.

## 4. 데이터 · 운영 규칙

- 리뷰·은어는 **학생이 쓰는 글**이다 → 신고·숨김 기능, 욕설 걸러내기, 운영자 삭제 권한이 처음부터 있어야 한다.
- 가게에 대한 허위 비방은 법적 분쟁 소지가 있다 → 이용약관에 게시물 책임·삭제 조항 추가(`terms.html`).
- **지어낸 리뷰·별점을 초기 데이터로 넣지 않는다**(운영 원칙 6 가짜 공지 금지와 같은 정신). 처음엔 비어 있는 것이 정직하다.
- 술집 정보는 만 19세 미만에게 노출하지 않는다(고등학생용 과외 앱과 장부를 공유하므로 서버에서 나이 확인).
- 위치는 **학교 위치 기준**으로만 검색한다. 학생의 현재 위치를 받으면 위치정보법 동의·고지가 추가된다 → 처음엔 받지 않는다.

## 5. 만드는 순서
1. (개발자) 카카오 개발자 앱 등록 → REST 열쇠를 **Cloudflare 시크릿**에 저장 (채팅에 붙여 넣지 않는다)
2. `server/places/` Worker: 학교 좌표 + 카테고리 → 장소 목록 (1일 캐시)
3. 앱: 찾기(또는 새 탭)에 「학교 주변」 — 목록 + 카카오맵 링크 (안 C)
4. Supabase `place_reviews` · `campus_slang` 표 + 자기 글만 고치는 규칙(RLS) + 신고 표
5. 반응이 좋으면 지도 그림(안 A)

## 6. 정할 것
1. 안 C로 시작해도 되는지 (외부 스크립트를 앱에 들이지 않는다)
2. 이 기능이 한대장 안에 들어가는지, 과팅 앱 쪽에 들어가는지 (술집·과팅 장소는 과팅 앱이 더 맞다)
3. 카카오 개발자 앱 등록 담당

## 7. 신입생 지도 시안 (2026-11-22)

> 지시: *"대학교 별로 학교 주변지도 기능을 추가하고 싶어. 특히 신입생을 위한 기능 … 지도 위에 수집된 데이터들이 시각적으로 (카공 스팟, 자취·생활 및 안전 인프라, 학생 복지 및 제휴 혜택)"* → *"직접 만들어서 시안 제시해볼래?"*
> 시안: `docs/designs/mockups/campus-map/index.html` (폰 화면 8장 · 시범 학교 서울과학기술대학교). 그림은 같은 폴더의 `shots/`.

**1~6절과 달라진 것**
- **지도 그림을 앱 안에** — 개발자가 "지도 위에 시각적으로"를 원해서 3절 안 C(목록 + 링크)로는 모자란다.
  새 **안 D**: 지도 그리는 프로그램(Leaflet · BSD-2)을 **저장소 사본**으로 두고 바탕 그림(타일)만 바깥에서 받는다 →
  바깥 스크립트 0 · CSP `script-src 'self'` 유지(`img-src` 에 타일 주소 하나만 더함). 시안이 이 방식으로 돈다.
  실서비스 바탕 그림 후보는 국토교통부 브이월드(무료 · 공공누리 1유형 · 회색·미드나잇 지도 · 열쇠 필요 — 타일 주소·한도는 사이트가 안 열려 확인 전).
  OSM 공식 타일은 시안에서만 — 정책이 Referer 를 요구하는데 앱 index.html 은 Referer 를 끈다.
- **지도 주제 여섯**: 학교 안 · 카공 · 생활 · 안전 · 교통 · 복지·혜택. 술집·과팅은 이번 지시에 없어 넣지 않았다(넣을지는 아래 정할 것 ⑥ · 옛 설계 4절은 나이 확인 뒤 노출).
- **한대장만의 연결 셋**: ⑥ 공고 「서류」 줄의 관공서 서류 → 가까운 무인민원발급기 · ⑦ 첫 주 코스에 원문에 적힌 장학 창구(과기대 「제2학생회관 201호」) · ④ 교내 소식 혜택 글을 장소에.
- 리뷰·별점·은어(1절)는 이번 시안에 없다 — 학생 글이라 신고·삭제 장치가 먼저다(4절).

**데이터 — 이번에 실제로 받아 본 것** (경위·실패 기록은 시안 「데이터」 표)
- OSM(api.openstreetmap.org): 정문 1.3km 안 장소 428곳 · 캠퍼스 경계 · 행정동 경계 8곳. 가게 수는 실제보다 적다(스터디카페 0 · 코인세탁 1) → 실서비스는 공공데이터·장소 검색으로.
- 서울 열린데이터광장 무인민원 발급기(OA-20336) · 안전비상벨(OA-15253): 받음 — **좌표 칸이 없어** 이름이 같은 시설 자리에 둔다.
- 공공데이터포털 전국CCTV·안전비상벨 표준데이터: 원본 서버(file.localdata.go.kr) 연결이 이 환경에서 끊겨 **못 받음** → 로봇이 GitHub 에서 받게.

**지킬 것(시안에서 정한 규칙 · 검토 셋 반영)**
- **핀은 남색 잉크 한 색, 갈래는 그림으로** — 초록·빨강·보라는 앱에서 이미 「선정·마감·공모전」 뜻이다. 고른 곳만 강조색 테두리 · 그 밖은 회색 점.
- 밝은 지도 한 벌(앱에 어두운 면이 없다) · 글자는 앱 척도 · 그림자는 토큰만 · 안쪽 화면 머리에 오른쪽 단추 없음.
- 거리는 정문에서의 **직선 거리**만(걷는 시간을 짐작하지 않는다) · 학생 위치는 받지 않는다.
- 안전은 **점수 없이** 시설만(틀린 안심 금지) · 「카공하기 좋음」 같은 평가는 짐작하지 않는다(원칙 8-1).
- 혜택은 원문 기간이 지나면 자동으로 내린다 · 글↔장소 잇기는 **관리자 확인**(같은 이름 카페가 여럿).
- 모르는 값(여는 시간 등)은 줄째 안 그린다 · 학생 화면에 앱 내부 사정(OSM·연결 예정)을 적지 않는다.
- 데이터는 학교별 파일 `data/map/<학교키>.json`(열쇠는 `noticeFileKey` 와 같은 규칙) — 폰은 자기 학교 것만.
- 하단 탭은 늘리지 않는다(5칸이 꽉 참) → 홈 「우리 학교 주변」 구역에서 들어간다.

- 동네 비교는 **개수 대신 이름으로 확인된 것**(역·치안센터·주민센터)만 — 공개 지도의 「0」은 「안 그려져 있다」일 뿐이고, 정문 1.3km 원 안에서만 세면 동마다 센 범위가 다르다.
- 안전 시트는 112·119 를 맨 위에 — 치안센터는 밤·주말에 비는 곳이 많아 개수로 앞세우지 않는다.
- 못 구한 데이터 자리는 시안에서만 노란 「시안 메모」 — 실제 앱에서는 데이터가 없으면 그 줄이 없다.

**정할 것(시안 「정해 주실 것」)** — ① 들어가는 곳(홈 줄 / 신입생에게만) ② 주제 하나씩·핀 한 색 / 겹쳐 보기·주제마다 색 ③ 바탕 지도(안 D 브이월드 / 안 A 카카오) ④ 혜택 글 잇기(관리자 / 로봇) ⑤ 안전 주제 어두운 지도 ⑥ 술집·과팅 장소(넣지 않음 / 나이 확인 뒤) ⑦ 「동네」 단위(법정동 — 월세 자료와 같음 / 행정동).

**개발자 결정 (2026-11-23 · 채팅)** — *"전부 추천안 A로 진행하되, 6번 넣고 7번은 동의 행정단위로 제한하지 말고, 각 대학의 대학가 (학생들의 최대 이동범위)로 묶어줘. 지도 내용은 재학생이 제안하고, 지도 내의 내용 또한 재학생의 리뷰 및 의견을 반영하도록 해줘. 최초 지도에 대해서는 직접 에타 등 여러 리소스의 대학생 커뮤니티를 직접 리서치하여 해당 정보를 반영해 제작해줘."*
- ①~⑤ 추천안 A 확정: 홈 줄로 들어감 · 한 번에 한 주제·핀 한 색 · 바탕 지도는 브이월드 + 저장소 지도 프로그램 · 혜택 글 잇기는 관리자 확인 · 밝은 지도.
- ⑥ **술집·과팅 장소를 넣는다.**
- ⑦ 동네는 행정동·법정동이 아니라 **대학가 구역**(학생들이 부르는 상권 이름 · 학생들의 최대 이동 범위까지).
- 새 요구 셋: **재학생이 장소를 제안** · **재학생 리뷰·의견을 지도에 반영** · **최초 지도는 학생 커뮤니티 리서치로 채운다**(8절).

**발견한 데이터 문제(시안 만들다 본 것 · 원인은 확인 안 함 · 고치지 않음)**
- 층2 「서울미래인재재단 서울선순환인재 장학금」은 「서울런 멘토 8개월 이상」만 받는데 과기대 1학년에게 적합도 95%로 보인다(그 조건 줄을 못 읽음).
- 「신용카드수수료장학금」(홍익대 장학팀 창구)이 전국으로 승격돼 있다 — 범위 승격 규칙(학교 창구 문장이 있으면 안 푼다)과 어긋나 보인다.
- 통영시 저소득 대학생 장학금이 두 건(과기대 게시판 · 연세대 게시판)으로 과기대 학생에게 둘 다 보인다.
- 교내 소식 한 글(과기대 items[32])의 요약에 다른 글 제목이 섞여 있다.

## 8. 재학생이 채우는 지도 — 대학가 구역 · 제안 · 의견 · 최초 지도 리서치 (2026-11-23)

> 시안 3판: `docs/designs/mockups/campus-map/index.html` (폰 화면 11장) · 리서치 자료 생성본 `town.js`.

**대학가 구역** — 행정동·법정동이 아니라 학생들이 부르는 이름으로 묶는다. 구역마다 기준 지점(역 출구·시장·문 등 공개 지도의 실제 좌표)을 두고,
학생들이 가장 멀리 다니는 일상 목적지까지가 그 학교의 대학가다. 과기대: 정문 앞 · 철길(경춘선숲길) · 공릉역 · 도깨비시장 · 협동문 · 하계역 · 태릉입구 · 화랑대 · 석계역 · 노원역(3.1km) — 열 곳. 바깥 끝(노원역)은 학보 문장 둘뿐인 가정이라 재학생 의견으로 다시 맞춘다. 익명 게시판 글에만 나온 구역(원자력 삼거리 · 월계 트레이더스)은 싣지 않았다.

**최초 지도 리서치 — 읽은 곳과 못 읽은 곳**
- 🔴 **에브리타임은 못 읽는다** — 학교 에타 첫 화면이 로그인 벽이고 사이트 규칙(robots.txt)도 첫 화면 말고는 막는다. 로그인·우회하지 않는다(원칙 9의 정신). 에타의 정보는 재학생이 「장소 제안」으로 옮긴다.
- 네이버 블로그·카페 · 인스타 · 페이스북 · 에펨코리아 · 인스티즈 · 레딧은 사이트 규칙이 로봇을 금지 → 읽지 않는다. 나무위키·오르비·더쿠는 접속 차단.
- **읽은 곳**: 학보(서울과기대신문 · 학생 기자 기사 — 가장 믿을 만하다 · 화면 인용의 대부분) · 학교 공식 안내 · 뽈레(리뷰 앱).
- 🔴 **디시 학교 갤러리도 읽었지만 쓰지 않는다** — 그 사이트 규칙은 일반 수집은 허용하되 Claude 를 포함한 AI 수집기를 이름으로 막는다(인스티즈·에펨코리아와 같은 꼴인데 그 둘은 안 읽었다 — 기준이 달랐다). 다음 학교부터는 이런 곳을 처음부터 읽지 않는다.
- 과팅 장소로 이름이 적힌 가게는 0곳 · 술집도 몇 곳뿐 → 빈 상태로 열고 재학생 제안으로 채운다.

**리서치 자료를 싣는 규칙**
- 요약·평가를 만들지 않는다 — **출처 문장 그대로(60자 이하) + 출처 이름·날짜·링크**(원칙 8-1). 싣기 전에 출처를 다시 열어 글자 대조한다(검증에서 ok 인 곳만).
- 익명 게시판 글은 인용하지도, 구역의 근거로 쓰지도 않는다(재학생인지 알 수 없다 · 그 사이트가 AI 수집기를 막는다). *(개발자 결정 대기 — 시안 「정해 주실 것」 5)*
- 가게를 깎아내리는 말·글쓴이 정보는 옮기지 않는다. 2025년 이후 영업 근거를 못 찾은 곳은 싣지 않는다.
- 위치를 못 맞춘 가게에 좌표를 지어 붙이지 않는다 — 핀 없이 목록에만(구역 이름으로). 좌표는 카카오 장소 검색 연결 뒤.
- 공개 지도의 낡은 값은 출처로 바로잡는다(예: 마을버스 노원13 → 노원03 · 통합 2025-12-15 · 학보 2026-01 기사).

**재학생 제안 · 의견**
- 제안: 재학생으로 확인된 계정 → 장소 이름·주제·구역·한마디 → **운영자 확인 뒤** 지도에(「게시 요청」과 같은 길 · 관리자 「할 일」).
- 의견: **별점 없이** 주제마다 정해진 좋은 말을 고르고(여러 개) 한 줄은 선택. 고른 사람 수가 장소 줄·시트에 뜨고 의견 많은 곳이 위로.
- 「틀린 정보 알리기」(문 닫았어요 · 위치가 달라요 · 이름이 달라요)가 세 명(가정)에게서 오면 내리고 운영자가 확인. 의견·제안에 글쓴이 이름·학번을 붙이지 않는다. 한 줄 의견은 신고·삭제 가능(4절).
- 🔴 **재학생 의견은 처음엔 비어 있다** — 지어 넣지 않는다. 장소 시트의 절 차례는 늘 「재학생 의견」→「학보·리뷰에서」→「교내 소식」. 모양만 보이는 예시는 폰 그림 밖 「시안 메모」로만.

**눌러 보는 시안(2026-11-24 · 개발자 요청 "직접 열어보고 누를 수 있는 파일")** — `docs/designs/mockups/campus-map/play.html` · 움직임 `play.js` · 틀 `play.css`.
- 그림 시안(`index.html`)의 화면을 폰 한 대 안에서 이어 붙였다. 화면 모양은 `play.html` 의 `<template>`(그림 시안에서 그대로 옮긴 생성본 — 손으로 고치지 말 것), 그림이 없던 주제(밥집·생활·교통·복지·혜택)·장소 시트·목록·구역 화면은 같은 부품으로 자료에서 만든다.
- 🔴 재학생 의견은 비어 있고 **이 기기에서 방금 남긴 것만** 「내가 남긴 의견」으로 보인다(어디에도 보내지 않는다 · 탭을 닫으면 사라진다). 재학생 확인도 메일을 보내지 않고 넘어간다고 화면에 적는다.
- 🔴 휴대폰에는 **주소로** 보낸다 — 휴대폰 Claude 앱은 HTML 파일을 화면으로 그리지 않고 글자로 보여 준다(11-24 실제로 그렇게 보였다). 앱 주소 아래 `docs/designs/mockups/campus-map/play.html`.
- 화면 높이가 기기마다 달라 지도 보기는 그릴 때 맞춘다(`frame` — 아래 판에 가리지 않는 칸 안에 핀이 다 보이게). 낮은 화면에서는 목록 판을 낮게 시작한다(`.peek`). 판 높이를 잰 뒤에 지도를 맞추므로 처음 그릴 때는 판을 움직이지 않는다(움직이면 옛 높이를 잰다).
- 고르는 말(밥집·술집·그 밖)과 「틀린 정보」 세 갈래는 시안에서 새로 적은 글자다 — 승인 전.

**새로 정할 것(시안 「새로 정해 주실 것」 · 시안은 전부 A)** — ① 재학생 확인(A 학교 메일 / 프로필만) ② 제안이 실리는 때(A 운영자 확인 뒤 / 바로) ③ 대학가의 바깥 끝(A 노원역까지 / 걸어 다니는 2km) ④ 에타를 못 읽은 자리(A 열기 전 재학생 몇 명에게 제안 화면으로 받기 / 빈 채로) ⑤ 익명 게시판 글(A 쓰지 않음 / 구역 근거로만 / 인용까지) ⑥ 술집·과팅을 누구에게(A 성인 프로필만 — 법 요구는 확인 전 / 모두) ⑦ 지시에 없던 주제(A 밥집은 칩 · 카페·놀거리는 제안 화면에서만 / 지시 주제만) ⑧ 의견 모양(A 정해진 말 / 별점).
**개발자 몫** — 카카오 개발자 앱 등록(장소 검색) · 브이월드 사용 신청 · 학보사에 인용 알리기 · 약관(학생 글 책임·삭제).

## 9. 방향 바꿈 — 네이버 지도 · 처음 지도 점수 · 토큰제 (2026-11-25 개발자 지시)

> 지시 셋: ① 지도는 **네이버 지도 API** ② **정보 입력 토큰제**를 염두에 두고 짓기(토큰제 자체는 다음 세션 — `docs/designs/contribution-tokens.md`) ③ 학생이 없는 처음 데이터는 **공공 API + 지도 기반 리서치 → 조건에 따른 적합도 점수 → 갈래별 상위 n곳만 지도에 → 장소마다 요약·장단점**.
> 앞 절에서 바뀌는 것: 7절 결정 ③(브이월드 + Leaflet) → 네이버 지도 · 8절 「요약·평가를 만들지 않는다」 → 아래 규칙 안에서 요약·장단점을 만든다.

**① 네이버 지도 — 확인한 사실(11-25 공식 문서)**
- 싣는 법: `https://oapi.map.naver.com/openapi/v3/maps.js?ncpKeyId=<Client ID>` — 2025년에 Maps 가 새로 나와 **옛 `ncpClientId` 가 아니라 새 Client ID** 가 필요하다(네이버 지도 API v3 시작 문서).
- 등록: 네이버 클라우드 플랫폼 콘솔 → Maps → Application 등록 → **Web Dynamic Map** 선택 + **Web 서비스 URL**(앱 주소)을 넣어야 등록이 끝난다. 무료 이용량은 **대표 계정에만**(요금표 검색 결과: Dynamic Map 월 600만 건 이하 무료 — 콘솔의 요금표로 한 번 더 확인할 것).
- 🔴 **보안 설정과 부딪힌다(3절)** — 앱은 `script-src 'self'` 라 네이버 스크립트를 못 싣는다. 지도 화면을 **따로 둔 쪽**(지도 전용 페이지 · 그 쪽에만 네이버 주소를 허용)으로 풀고 앱 본체의 설정은 그대로 둔다. *(개발자 결정 대기)*
- 🔴 열쇠가 없어 **네이버 지도로는 아직 한 번도 그려 보지 못했다** — 눌러 보는 시안의 바탕은 지금도 오픈스트리트맵이다. 열쇠가 오면 `map-mock.js` 의 그리기(핀 · 번호 · 이름표 · 구역 원 · 보기 맞추기)를 네이버 지도용으로 옮기고 **등록한 주소에서** 실제로 눌러 본다.
- 장소 시트의 단추는 「네이버 지도에서 보기」(`map.naver.com/p/search/<이름>`)로 바꿨다 — 🔴 네이버 지도가 내 접속을 막아 **이 주소가 뜻대로 열리는지는 확인하지 못했다.**

**③-가. 「지도 기반 리서치」로 할 수 있는 것과 없는 것**
- 🔴 **네이버 지도·카카오맵의 장소 화면(별점·리뷰)은 읽지 않는다** — 두 곳 모두 사이트 규칙 첫 줄에 「AI 학습·검색 보강 목적의 봇 접근을 엄격히 금지」를 적고 Claude 계열을 이름으로 막는다(11-25 `robots.txt` 직접 확인). 에타와 같은 까닭.
- 쓸 수 있는 정식 길: **네이버 지역 검색 API**(하루 25,000회 · 한 번에 최대 5곳 · 이름·분류·주소·좌표 — **별점·리뷰 수는 주지 않는다**. `sort=comment` 로 카페·블로그 리뷰가 많은 차례는 받을 수 있다) · **카카오 로컬 API**(반경 안 분류 검색 · 좌표) · 공공데이터(상가정보 · 인허가). 전부 열쇠가 필요하고 로봇(GitHub Actions · 시크릿)에서 돈다.
- 그래서 **학생들의 별점은 처음 데이터로 구할 수 없다** — 그 자리는 재학생 의견(토큰제)이 채운다.

**③-나. 처음 지도 점수 — `docs/designs/mockups/campus-map/score.js` 한 곳** (브라우저·Node 겸용 — 로봇이 같은 파일을 불러 쓴다)
- 100점 = **가까움 30**(정문 거리 · 핀이 없으면 구역 거리로 어림하고 3점 깎음) + **근거 30**(겹치지 않는 글의 수 + 재학생 기자·학교 글이면 5) + **최근 15**(가장 새 글이 1년 안 15 · 2년 10 · 3년 6) + **조건 15**(갈래마다 정한 조건이 글 속 낱말로 확인될 때마다 5 — 카공: 예약 없이 · 콘센트 · 조용 … / 밥집: 값 · 혼자 · 단골 … / 술집: 재학생 · 단체 · 값) + **위치 확인 10**.
- 갈래마다 점수 높은 차례로 **상위 5곳(`TOPN`)만 번호 핀**. 나머지는 「목록 보기」에.
- 🔴 **지어내지 않는다** — 요약·장점·「아쉬운 점·확인할 것」은 자료에 있는 사실(거리 · 글의 수와 날짜 · 출처 · 글 속 낱말 · 핀 유무)에서만 나오고, 글에서 나온 줄에는 그 구절을 근거로 붙인다. 맛·분위기·별점처럼 자료에 없는 것은 만들지 않는다(원칙 6 · 8-1 을 지도에서는 이렇게 푼다 — 11-25 개발자 지시).
- 🔴 화면에 **「학생 평가가 아니라 자료로 매긴 처음 점수」** 라고 적는다. 재학생 의견이 쌓이면 의견이 먼저 보인다(섞는 식은 토큰제와 함께 정한다).
- 공공 자료 주제(학교 안 · 생활 시설 · 안전 · 교통)는 점수 없이 가까운 차례 그대로.
- 지금 점수가 얇은 까닭: 조건을 확인할 자료가 학보·리뷰 글뿐이다(영업시간 · 값 · 좌석 수 같은 칸이 없다). 지역 검색 열쇠가 오면 좌표(핀 없는 가게 20곳)와 분류가 붙는다.

**개발자 몫(이 절)** — ① 네이버 클라우드 Maps Application 등록(Web Dynamic Map · 서비스 URL = 앱 주소) → Client ID ② 네이버 지역 검색(또는 카카오 로컬) 열쇠를 GitHub 시크릿에 ③ 지도 화면을 따로 둘지(보안 설정) ④ 점수 식의 비중과 `TOPN`.
