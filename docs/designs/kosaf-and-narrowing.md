# 교외 장학금 채널 재설계 — 조사 결과와 다음 세 작업 (2026-08-30)

> 2026-08-29~30 세션의 조사 결론이다. **다음 세션은 이 문서만 읽으면 바로 이어서 할 수 있다.**
> 조사는 끝났고 데이터도 받아 뒀다(`data/kosaf.json`). 남은 건 실행 셋뿐이다.

## 왜 이 조사를 했나

개발자 지시: 학교를 **경희대·한국외대 두 곳으로 줄이고**, 교외 장학금은
**한국장학재단(KOSAF) 통합검색**으로 대체할 수 있는지 보라.

동기는 검수 부담이 아니라 **품질**이다 — *"공고 양식이 제각각이라 자격요건 매칭이나
양식 스키마화에서 자꾸 못 읽겠다고 한다. 학교를 줄여 공고를 줄이면 더 완벽하게
할 수 있지 않을까."*

## 확정된 사실 (재조사 금지)

### KOSAF 로 할 수 있는 것
- 재단 **1,868곳** 목록. 우리 민간 재단 36곳이 **100% 등재**돼 있다.
- 상세에 **20개 칸이 100% 채워져** 있다 — 이 저장소가 원문에서 힘겹게 뽑던 것들이다:
  `학년구분 · 학과구분 · 성적기준 · 소득기준 · 지원금액 · 특정자격 · 지역거주구분 ·
   신청기간 · 선발인원 · 자격제한 · 제출처 및 제출서류 · 문의처 · 홈페이지주소`
- **지자체 장학금 94건**은 순증(지금 우리 앱에 거의 0인 영역). 프로필의 `region`으로 매칭 가능.

### KOSAF 로 **못** 하는 것
- 🔴 **이번 회차를 모른다.** 우리 재단 36곳 중 KOSAF 가 '지금 모집 중'으로 아는 건 **7곳(19%)**.
  나머지 29곳은 지난 회차를 들고 있다. 상세의 `신청기간`도 목록의 `모집마감일`과 **95% 같다**
  (상세가 더 최신이 아니다 — 확인함).
- 🔴 **신청서 양식 첨부가 없다.** 첨부는 0~1개(공고문)뿐이고 `공고문 없음.hwp` 같은 **더미**도 있다.
  앱의 '양식 작성' 기능은 학교 게시판이 첨부를 여러 개 주기 때문에 가능했던 것이다
  (우리 앱: 첨부 2개 이상 67건 · 신청서류 첨부 76건 · formId 연결 38건).

### 🔴 조사 중 드러난 우리 쪽 결함 (가장 급함)
살아있다고 표시 중인 교외 58건 중 **39건이 기한미상**이고, 그중 **32건은 원문에 날짜가 있다.**
파서가 못 읽어 `notStale` 60일 규칙으로 버티는 중이라 **이미 끝난 공고를 학생에게 보여주고 있다.**
KOSAF 와 대조된 12건은 **전부** "이미 지남"이었고, 원문의 날짜도 전부 7월이었다.

### 축소했을 때의 손익 (분모를 바로잡은 값)
"살아있는 교외 58건"은 부풀려진 숫자다 — 마감일이 확실한 건 19건뿐이다.

| | |
|---|---|
| 확실한 손실 | **12건** |
| 불확실한 손실(살았는지 모르는 것) | 25건 |
| 손실 아님(이미 죽은 것을 내리는 것) | 9건 |
| KOSAF 가 메워 주는 민간 이번 회차 | **거의 0건** |
| KOSAF 가 더해 주는 것 | 지자체 94건 + 자격요건 20칸 |
| 품질 이득 | 못 읽은 공고 67 → **7건** · 교외 재단 형식 32 → **6곳** |

⚠️ 재단 중복이 거의 없다(32곳 중 27곳이 한 학교에서만 나옴) — 학교를 빼면 그만큼 그대로 사라진다.
⚠️ 경희·외대 학생이 보는 화면 자체는 거의 안 줄어든다(11·17건 → 19건). 매칭이 학교별이라
   원래 남의 학교 공고는 안 보였다. 문제는 드림스폰(수백 건)과 비교될 때다.

### 드림스폰 (경쟁사) — 표본 15건
KOSAF 와 **10건 겹침**. 다만 그냥 따오는 것은 아니다: `장학금등록/광고` 메뉴로 **재단이 직접 등록**하고,
청년정책(전월세·청년도전)까지 범위가 넓으며, 자체 `드림장학금`과 개인 후원(치과·안과)이 있다.
→ 재단 직접 등록은 **학생 트래픽이 먼저** 있어야 성립한다. 순서를 건너뛸 수 없다.

## 🔴 KOSAF 를 다시 받는 법 (알아내는 데 오래 걸렸다)

`node collector/kosaf-fetch.mjs [--only=낱말파일] [--max=N] [--write]`

- 목록 GET → 쪽 넘김은 `no=` 로 `POST /CO/jspActionSafe.do`
- **상세는 `form2` 의 칸을 그대로 보낼 것.** 덮어쓰면 안 된다 —
  `inputVOName` 이 `…PTSMCstmDsgnGoodsDtlSVO` 인데 `Dtl` 을 빼면
  **200 인데 본문 없는 껍데기(67KB)** 가 온다. 이걸 몰라 상세 0건이 나왔고 원인을
  '토큰'·'헤더'로 두 번 잘못 짚었다.
- 첨부는 **Referer 만 있으면** 받아진다(쿠키 불필요). 리퍼러 없이는 "비정상적인 접근".
  ⚠️ 우리 앱은 리퍼러를 안 보내므로 **그 주소를 앱에 그대로 넣으면 학생이 못 받는다.**
  → 로봇이 받아 `collector/extracted/` 에 두거나, KOSAF 상세 링크를 준다.
- 로그인은 필요 없다. "로그인이 필요한 서비스" 문구는 목록에도 있는 **숨은 모달**이다.

## ④ 층2에 '공고 원문'을 붙였다 — 재단 홈페이지 하나만 주던 구조의 수리 (2026-09-12)

개발자 지시: *"KOSAF 에서 크롤링 해오는 외부 공고들은 신청 양식 / 첨부파일 / 원문 공고 링크만
없고 해당 장학 재단으로만 이동할 수 있는 구조인 것을 확인해왔어. 이를 해결하기 위한 방법을
수립하고 즉시 직접 작업 시작해줘."*

### 왜 그런 구조였나 — 원인 셋

| | |
|---|---|
| ① 첨부 링크를 **글자로 뭉갰다** | 상세 파서(`parseDetailFields`)가 `strip()` 으로 태그를 지운다. 그 태그 안에 유일한 원문(선발공고문)으로 가는 길이 있었는데, 남은 것은 `선발공고문: "[다운로드]"` 라는 **아무 쓸모 없는 글자**였다 |
| ② 담아도 **학생이 못 받는다** | KOSAF 첨부는 Referer 검사가 있다. 앱은 리퍼러를 안 보내므로(index.html 정책) 그 주소를 담으면 화면에 "비정상적인 접근"이 뜬다 |
| ③ 상세 화면은 **POST 전용** | 학생에게 줄 주소가 아예 없다. 그래서 `sourceUrl` 이 재단 홈페이지였다 |

### 무엇을 했나 — '링크를 담기'가 아니라 '받아서 두기'

`collector/kosaf-attach.mjs` 가 **리퍼러를 붙여 받아** `data/kosaf-files/<재단코드>/` 에 둔다.
학생은 우리 도메인에서 받으므로 리퍼러가 필요 없다. 앱 파일에 담기는 것은 **우리 쪽 경로뿐**이고,
kosaf.go.kr 주소가 섞이면 관문(`kosaf-check.mjs`)이 막는다.

- 포털과 말하는 규칙(쿠키·csrf·form2·Referer)은 **`collector/kosaf-session.mjs` 한 곳**으로 모았다 —
  로봇이 셋(수확·첨부·정찰)이 되면서 베끼면 갈라진다.
- 받아 둔 공고문에서 **글자를 뽑는다**(`hwp-prvtext.py`·`pdf-text.py` 에 폴더 인자 추가 +
  **hwpx 지원 신설**). 이것이 마감일·자격·검색·**신청 양식 스키마화**의 재료가 된다 —
  지금까지 층2에는 그 재료가 한 글자도 없었다.
- 링크 이름을 사실에 맞췄다: 층2의 `sourceUrl` 은 KOSAF 가 아니라 **그 재단 홈페이지**인데
  화면은 '한국장학재단 ↗' 이라고 적고 있었다(눌러 보면 안 열린다) → '재단 홈페이지 ↗'.

### 🔴 이 작업에서 실제로 밟은 함정 (되돌리지 말 것)

1. **첨부 칸을 낱말로 찾으면 96%가 엉뚱한 행을 집는다.** `선발공고문` 은 상세표의 **맨 마지막
   칸**이고, 그보다 앞 칸(`자격제한`·`제출처 및 제출서류`)에 `※ 자세한 사항은 첨부파일 또는
   홈페이지 참고` 라는 상투구가 거의 항상 있다(실측 1,587곳 중 **1,525곳**).
   → 이름표 칸(`<th>선발공고문</th>`)을 찾아 **그 다음 칸만** 본다(`fileCellHtml`).
   🔴 더 나쁜 것은 **조용하다는 것**이다 — 첨부가 0건이 되면 새 관문 셋이 전부 빈 목록을
   상대로 통과한다(초록불). 그래서 `kosaf-check.mjs` 가 **'[다운로드] 가 적힌 곳 수'와
   '실제로 링크를 읽은 곳 수'를 나란히** 본다.
2. **디스크 경로를 URL 로 다루면 이름에서 깨진다.** `(등록금 100% 지원).hwp` 는 퍼센트 escape 로
   읽혀 `URIError` 로 실행을 죽이고, `공고문#2.pdf` 는 `#` 뒤가 잘려 장부와 다른 이름으로
   저장된다(그러면 관문이 실패해 **그날 수확분까지 저장이 건너뛰어진다**). 경로는 `path.join`,
   디스크 이름에서 `%`·`#` 를 뗀다(보여 주는 이름은 원문 그대로 따로 남긴다).
3. **서비스워커가 공고문을 가로채면 안 된다.** `target="_blank"` 로 여는 PDF 는 `mode==='navigate'`
   라 느린 회선에서 **3.5초 시한에 걸려 index.html 이 대신 나간다**(공고문을 눌렀는데 앱이 또
   열린다). 게다가 건당 0.2~2MB 를 캐시에 쌓는다 → `data/kosaf-files/` 는 브라우저에 맡긴다.
4. **`safeUrl` 의 기준이 `location.origin` 이면 우리 파일을 못 찾는다.** 앱은
   `…github.io/hanggonggan/` 에 있는데 origin 기준으로 풀면 사이트 뿌리로 새서 404 다
   → `document.baseURI`. ⚠️ **이 검사는 처음에 무력했다** — 검사 서버는 앱을 뿌리에 두므로
   두 기준의 결과가 같다. `verify-kosaf.js` 가 배포 자리를 흉내 내 다시 푼다.
5. **`--write` 없이 받거나 지우지 않는다.** 처음엔 화면에만 '(미리보기)'라 찍고 파일을 실제로
   받고 지난 회차 폴더까지 지웠다.
6. **중간에 멈춰도 받아 둔 것은 장부에 적는다**(`keep()`). 안 그러면 커밋될 파일이 장부에 없는
   '주인 없는 이진 파일'이 되고 다음 실행이 같은 것을 또 받는다.
7. **재단이 새 회차로 갈아 끼우면 다시 받는다** — 파일이 있다는 것만 보면 지난 회차 공고문을
   영영 보여 준다(`mirror.from` 에 받아 온 주소를 적어 두고 대조한다).
8. **저장소가 회차마다 불어나지 않게** 마감된 재단의 사본은 지운다(`prune`) · 한 파일 12MB ·
   한 실행 40MB 상한.

### 🔴 신청 양식은 붙이지 않았다 — 붙이면 가짜가 된다 (실측 근거)

받아 둔 60건을 `schema-from-text.mjs`(무료·규칙 기반)에 그대로 물려 보았다.

  KOSAF 가 재단당 올려 두는 파일은 **선발공고문 하나**이고, 진짜 신청서 양식은
  재단 홈페이지에 있다.
- 그런데 변환기는 **12건을 '변환 성공'이라고 답했다.** 그중 11건은 공고문 글자를
  억지로 칸으로 만든 것이라(`있음 ( ), 없음 ( )` 같은 라벨) **원본과 다른 문서**가 된다.
  → 운영 원칙 4(원본 신청서와 **동일한 구조**여야 한다)를 정면으로 어긴다.
- 공고문 안에 서식이 함께 든 경우를 세어 보니 `[서식 n]` 표식을 가진 파일은 **0건**이었고,
