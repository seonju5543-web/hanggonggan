# 보안 자동 점검 — Dependabot · CodeQL

> 2026-11-11 · 유은서(CTO) · 출시 전 백엔드 10번
> 사람이 일일이 보지 않아도 **부품의 알려진 구멍**과 **우리 코드의 보안 구멍**을 GitHub 이 찾아 알려 준다. 둘 다 공개 저장소라 무료.

## 무엇이 도는가

| 점검 | 무엇을 | 언제 | 알림 |
| --- | --- | --- | --- |
| **Dependabot 판 올림** (`.github/dependabot.yml`) | 워크플로 부품(actions/checkout 등) · 푸시 서버 배포 도구(wrangler) | 매달 1회, 종류마다 **PR 하나로 묶어서** | PR 이 열린다(저절로 합쳐지지 않는다) |
| **Dependabot 보안 수리** | 알려진 보안 구멍이 있는 부품 | 즉시 | PR + 저장소 Security 탭 — 🔴 **저장소 설정 스위치가 켜져 있어야** 한다(아래) |
| **CodeQL** (`.github/workflows/codeql.yml`) | 우리 코드 — 자바스크립트(앱·로봇·서버) · 파이썬 · 워크플로 | 매주 월요일 02:51 + 기본 브랜치에 코드가 바뀔 때 | 심각(high·critical)·오류 수준이 열려 있으면 **세 사람에게 「🛡 보안 코드 점검에서 고칠 것이 나왔습니다」 이슈** · 다 고치면 저절로 닫힌다 |

## Dependabot PR 이 오면

1. 그냥 합치지 않는다 — PR 에서는 앱 검사(verify-ui)가 돌지 않는다.
2. Claude 세션에 **"Dependabot PR #번호 확인하고 합쳐줘"** 라고 한다. 세션이 관문(`DOC_GATES=1 node verify/test-collector.mjs` · `node verify/health-gates.mjs`)을 돌리고, 통과하면 기본 브랜치로 합친다.
3. 푸시 서버(wrangler) 판 올림을 합치면 `push-deploy.yml` 이 운영 서버에 다시 올린다(Cloudflare 열쇠가 있을 때).

관문 정규식은 부품 판 번호(`@v4`)를 박지 않는다 — 박으면 판 올림 PR 마다 관문이 빨개진다(2026-11-11 모의로 넷을 찾아 고쳤다 · 관문 「⑦ 보안 자동 점검」).

## CodeQL 경보가 오면

- Claude 세션에 **"보안 점검 경고 고쳐줘"**.
- 잘못 짚은 경고(실제 위험 없음)는 저장소 **Security → Code scanning → 그 경고 → Dismiss → False positive** 로 닫고 이유를 적는다. 다음 실행부터 세지 않는다.

## 🔴 이선주 님(저장소 주인)만 켤 수 있는 스위치

GitHub → 저장소 **Settings → Advanced Security**(예전 이름 Code security and analysis):

| 스위치 | 켤 것 | 왜 |
| --- | --- | --- |
| Dependency graph | 켬 | 아래 둘의 바탕 |
| Dependabot alerts | 켬 | 부품 구멍 알림 |
| Dependabot security updates | 켬 | 구멍 난 부품을 고치는 PR 을 즉시 |
| Secret Protection → **Push protection** | 켬 | 누가 실수로 열쇠 값을 커밋하면 push 자체를 막는다 |
| Code scanning → CodeQL analysis | **Default 로 바꾸지 말 것** | 우리 워크플로(고급 설정)와 부딪혀 분석이 올라가지 않는다 |

관문: `verify/health-gates/ops.mjs` 「⑦ 보안 자동 점검」 · 경보 본문 `tools/codeql-alerts.mjs`.
