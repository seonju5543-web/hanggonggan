# 홈페이지 · PC 버전 웹사이트 계획

> 2026-10-10 · 유은서(CTO) · 팀 업무 분장 백엔드 5번
> 지시: "홈페이지와 웹사이트를 분리하여 제작 검토 · 타 기업 레퍼런스 참고 · 시중 제작 툴 활용 (Research → Reference Look Up → Apply)"
> ⚠️ 이 작업 환경에서는 외부 사이트 접속이 대부분 막혀 레퍼런스는 **알려진 서비스 구조를 기준**으로 적었다. 실제 화면 캡처 비교는 사람이 브라우저로 한 번 더 본다.

## 1. 무엇을 둘로 나누나

| | 홈페이지 (소개) | PC 웹 (서비스) |
|---|---|---|
| 누구를 위해 | 처음 온 학생·학부모·재단·학교 장학팀·투자자 | 이미 쓰는 학생이 PC에서 |
| 하는 일 | "한대장이 뭔지" 설명 + 앱 설치 유도 + 제휴 문의 | 공고 찾기·신청서 작성·서류 정리 (앱과 같은 기능) |
| 주소 | `handaejang.kr` (대표) | `app.handaejang.kr` (지금 앱) |
| 바뀌는 빈도 | 가끔 (마케팅 문구) | 매일 (로봇 데이터) |
| 만드는 법 | **제작 툴** (코드 없이) | **지금 앱 코드에 넓은 화면 배치를 더함** |

나누는 이유: 소개 페이지는 마케팅 담당이 코드 없이 자주 고쳐야 하고, 서비스는 로봇·검사와 묶여 있어 함부로 고치면 안 된다.

## 3. Reference Look Up — 제작 툴 비교 (홈페이지용)

| 툴 | 비용(월) | 장점 | 단점 |
|---|---|---|---|
| **Framer** | 약 $15~ | 디자인 자유도 최고, 애니메이션, 사용자 도메인 | 영어 화면 |
| Webflow | 약 $14~ | 섬세한 제어, CMS | 배우는 데 시간 |
| 아임웹 | 약 1~2만 원 | 한글, 국내 결제·문의 폼 | 디자인이 템플릿 느낌 |
| Notion + oopy | 약 $9~ | 가장 빠름, 팀 모두 수정 가능 | 서비스 소개용으로는 밋밋 |
| 직접 HTML (저장소) | 0원 | 무료, 앱과 디자인 공유 | 수정할 때마다 개발자 필요 |

**권장: Framer.** 사장님·마케팅 담당이 직접 고칠 수 있고, 한 장짜리 소개 페이지는 하루면 만든다.
비용을 0으로 하려면 저장소에 HTML 한 장(지금 C안 시안 디자인 재사용)으로 시작하고, 수정이 잦아지면 Framer로 옮긴다.

## 4. Apply — 만드는 순서

### 홈페이지 (한 장, 섹션 5개)
1. 맨 위: "프로필 한 번이면, 내가 받을 수 있는 장학금이 다 보여요" + 큰 숫자(등록 공고 수·학교 수 — **실제 데이터 숫자만**) + [앱으로 시작하기]
2. 어떻게: 프로필 → 맞춤 공고 → 신청서까지 (화면 3장)
3. 대외활동·공모전도 한곳에서
4. 학교·재단 담당자께: 제휴 문의 (장학팀 파일럿 제안서 연결)
5. 아래: 개인정보처리방침·이용약관·문의 메일

🔴 **지어낸 숫자·가짜 후기를 쓰지 않는다**(운영 원칙 6). "누적 사용자 n명"은 실제로 셀 수 있을 때만.

### PC 웹 (지금 앱 확장)
- 화면 폭 1024px 이상이면 **왼쪽 메뉴 + 가운데 목록 + 오른쪽 상세**로 배치 (지금 아래에서 올라오는 상세 창을 오른쪽 칸에 띄움).
- 기능 코드는 그대로, `style.css`에 넓은 화면 규칙만 더한다. 인터페이스 전면 개편(C안)과 **같이** 하는 것이 효율적이다 — C안 확정 뒤 묶음 ①(기반)에 넣는다.
- 신청서 작성·AI 초안은 PC에서 훨씬 편하다(키보드). PC 웹의 핵심 가치가 여기다.
