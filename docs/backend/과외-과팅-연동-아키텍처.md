# 과외 · 과팅 기능 연동 아키텍처 검토

> 2026-10-10 · 유은서(CTO) · 팀 업무 분장 백엔드 6·7번
> 지시: 과외(고등학생용·대학생용)와 과팅을 **별도 앱으로 분리**하고 한대장과 연동. 채팅방 공유·과외 신청/문의/제안 같은
> 앱 간 상호작용이 가능한지 확인. 과팅은 차후 요금제 모델로.

## 1. 결론

**가능하다.** 핵심은 "앱은 셋, 회원 장부는 하나"다.

```
            ┌──────────── 한 회원 장부 (Supabase 프로젝트 1개) ────────────┐
            │  회원 · 프로필(학교·학과·학년) · 채팅방 · 과외 요청 · 과팅 매칭  │
            └───────▲───────────────▲────────────────────▲────────────────┘
                    │               │                    │
             한대장(장학금)      과외 앱(고딩/대딩)        과팅 앱
             app.handaejang.kr   tutor.handaejang.kr     meet.handaejang.kr
```

- 로그인 한 번이면 세 앱 모두 쓴다. 이미 쓰는 Supabase가 여러 앱의 로그인을 지원하므로 **새 서버를 사지 않아도 된다.**
- 학교·학과 정보는 한대장이 이미 가지고 있어 과외·과팅 앱에서 다시 묻지 않는다.
- 세 앱이 같은 도메인 아래(`*.handaejang.kr`)에 있으면 로그인 유지가 쉽다 → **도메인 구매(백엔드 1번)가 선행 조건.**

## 2. 앱 간 상호작용 — 무엇이 되나

| 하고 싶은 것 | 방법 | 난이도 |
|---|---|---|
| 같은 계정으로 로그인 | Supabase 한 프로젝트 공유 | 쉬움 |
| 채팅방 공유 (한대장에서 연 대화를 과외 앱에서 이어 보기) | 채팅 표를 장부에 두고 두 앱이 같은 표를 읽음. 실시간 전달은 Supabase Realtime | 중간 |
| 과외 신청·문의·제안 | `tutor_requests` 표(누가·누구에게·어떤 과목·상태). 상대 앱에 알림은 기존 푸시 서버 재사용 | 중간 |
| 한 앱에서 다른 앱 화면 열기 | 주소 링크(`tutor.handaejang.kr/req/123`) — 설치형이면 그 앱으로 열림 | 쉬움 |
| 과팅 요금제 | 결제(토스페이먼츠 등) + `subscriptions` 표, 서버에서 권한 확인 | 중간~높음 |

## 3. 과외 앱 구조

**고등학생용 ("에타 고딩편")**: 학원 정보 지도·로드맵, 커뮤니티, 대학생 과외 선생님 찾기.
**대학생용**: 내신/수능/면접 준비/논술 탭별로 과외 가능한 학생 목록, 받은 요청 관리.

필요한 표(초안):
| 표 | 담는 것 |
|---|---|
| tutor_profiles | 대학생 선생님: 과목·가능 지역·시급·소개 (학교·학과는 회원 프로필에서) |
| tutor_requests | 고등학생 → 선생님 요청: 과목·희망 시간·상태(보냄/수락/거절) |
| chat_rooms / chat_messages | 1:1 대화 (과외·과팅 공용) |
| posts / comments | 커뮤니티 |

## 4. 과팅 앱 구조
- 같은 학교 인증(학교 메일 인증 또는 한대장 학적정보)을 바탕으로 학교·학과 단위 단체 미팅 매칭.
- 요금제: 무료 n회 + 유료 이용권. 결제 확인은 **반드시 서버에서**(앱에서 판단하면 조작된다).
- 지도 기능(프론트 16번: 주변 술집·과팅 장소·카페 리뷰)을 여기서 함께 쓴다.

## 5. 🔴 반드시 지켜야 할 것 (법·안전)

1. **미성년자 보호** — 고등학생은 대부분 만 14~18세다.
   - 만 14세 미만 가입은 **법정대리인 동의**가 필요하다(개인정보보호법).
   - 고등학생과 성인(대학생)이 1:1로 대화하는 구조는 **보호 장치가 필수**: 연락처 바로 교환 금지(앱 안 대화만), 신고·차단, 대화 기록 보존, 선생님 본인·재학 인증.
   - **과팅 앱에는 고등학생이 절대 들어오지 못하게** 나이·학적 확인을 서버에서 막는다. 세 앱이 장부를 공유하므로 이 경계가 특히 중요하다.
2. **과외 중개** — 돈을 받고 과외를 중개하면 학원법상 신고 대상이 될 수 있다. 결제를 중개하기 전에 법률 확인이 필요하다.
3. **개인정보** — 장학금용으로 받은 정보(소득구간·특별자격 등)를 과외·과팅 앱에서 쓰면 **목적 외 이용**이다. 앱마다 동의를 따로 받는다.
   장부는 공유해도 **표마다 "어느 앱이 읽을 수 있나"** 규칙을 둔다.
4. 결제·위치정보를 다루면 위치정보법·전자상거래법 고지가 추가된다.

## 6. 권장 순서
1. 도메인 구매 → 2. 회원 장부에 공용 표(채팅) 설계 → 3. 과외 앱 대학생용 먼저(성인끼리라 위험이 낮음)
→ 4. 고등학생용(보호 장치와 함께) → 5. 과팅(결제·나이 확인과 함께).
**1~2는 한대장 작업과 겹치지 않아 바로 시작할 수 있다.** 3 이후는 법률 확인(5절 1·2)을 먼저 받는다.
