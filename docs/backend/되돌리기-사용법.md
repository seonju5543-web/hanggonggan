# 직전 판으로 되돌리기 — 사용법

> 2026-11-11 · 유은서(CTO) · 출시 전 백엔드 8번
> 앱이 이상해졌을 때, 원인이 된 **사람의 작업 하나**를 버튼으로 취소하고 앱에 내보낸다. 세 사람 누구나 할 수 있다(휴대폰 GitHub 앱도 된다).
> 버튼: GitHub → Actions → **「직전 판으로 되돌리기」** · 도구 `tools/rollback.mjs` · 워크플로 `.github/workflows/rollback.yml`

## 순서

1. **미리보기** — Run workflow → 모드 `미리보기` · 작업 번호 비움 → 실행.
   결과 요약에 **최근 사람 작업 10개**(번호·날짜·누가·무엇을)가 나온다. 아무것도 바뀌지 않는다.
2. (선택) 의심 가는 작업의 번호를 넣고 다시 `미리보기` — 그 작업을 되돌리면 **어떤 파일이 어떻게 바뀌는지** 보인다.
3. **되돌리기** — 모드 `되돌리기` · 작업 번호에 그 번호 · 이유를 적고 실행.
   - 취소 기록을 만들고 → 규칙 검사·데이터 감사를 돌려 **통과해야만** 저장한다.
   - 저장하면 배포 동기화를 바로 깨워 앱에 나가고, 몇 분 뒤 「실제 앱 반영 확인」을 돌린다.
   - 세 사람에게 「↩ 되돌림」 기록 이슈 메일이 간다.
4. 학생 폰은 앱을 **다시 열 때** 새 판을 받는다(재설치 필요 없음).

## 버튼이 하지 않는 것 (일부러)

| 하지 않는 것 | 이유 |
| --- | --- |
| 번호 없이 '가장 최근 작업' 바로 되돌리기 | 급할 때 엉뚱한 작업을 되돌리기 쉽다(2026-11-11 결정) |
| 로봇 작업(수집 기록) 되돌리기 | 공고 데이터가 사라진다 — 데이터는 관리자 화면에서 고친다 |
| 합치기(merge) 기록 되돌리기 | 어느 쪽을 되돌릴지 사람이 정해야 한다 — 그 안의 작업 하나를 고른다 |
| 워크플로 파일(.github/workflows)을 고친 작업 | GitHub 이 로봇 열쇠로 워크플로 파일을 고치는 push 를 거절한다 — Claude 세션에서 되돌린다 |
| 기록 되감기(강제 덮어쓰기) | 그 사이 로봇이 모은 공고와 다른 사람의 작업이 사라진다 |

## 이럴 때는

- **"부딪혀서 되돌릴 수 없어요"** — 그 뒤에 같은 곳을 또 고친 작업이 있다. 아무것도 바뀌지 않았다. Claude 세션에 "작업 ○○ 되돌려줘"라고 지시한다.
- **검사에서 멈춤** — 되돌린 판이 다른 규칙을 깬다. 저장되지 않았다(앱 그대로). 실패 이슈의 로그를 Claude 세션에 넘긴다.
- **되돌린 것을 다시 살리기** — 기록 이슈에 적힌 **되돌림 기록 번호**를 넣어 같은 버튼으로 되돌린다.
