# 슬라이드 구성안 (설계안 — 실제 덱이 아님)

> ## ⚠️ 이 문서는 정본이 아니다
> **실제 발표자료는 개발자가 외부 플랫폼에서 직접 만든 PPT다.**
> 이 문서는 제작 과정에서 세운 **설계안**이며, 최종 덱과 장수·순서·문구가 다를 수 있다.
>
> **대본은 개발자가 제시하는 실제 PPT를 기준으로 쓴다.**
> 이 문서는 그때 참고할 것 — 각 장의 임무, 시간 배분의 논리, 어느 장에 무게를 실었는지,
> 백업 슬라이드가 어떤 질문에 대응하는지가 정리돼 있다. 실제 덱이 달라도 이 논리는 그대로 쓴다.
>
> 실제 PPT를 받으면 **먼저 대조**해 장수·순서를 파악하고, `04_예상질의응답.md`의
> 백업 슬라이드 번호를 실제 번호로 다시 매길 것.

## 전체 구성

**본편 11장 (7분) + 질의응답용 백업 8장 = 19장**

백업은 발표 중에 넘기지 않는다. 질문이 나올 때만 연다.

### 배분의 논리
**4·5·6·7번에 발표의 절반(3분 30초)을 몰았다.** 이 네 장이 "실제로 만들었다"를 증명하는
자리이고, 나머지는 그 증명을 받치는 맥락이다. 대부분의 학생 창업팀이 목업을 들고 오는 자리에서
이 네 장이 팀을 다른 범주에 놓는다.

**11번을 15초로 짧게 둔 이유**: 마지막은 설명하는 자리가 아니라 요청하는 자리다.
"주소가 필요합니다" 한 문장으로 끝내고 질의응답으로 넘긴다.

## 본편 각 장의 내용 (키워드형)

### 1 — 표지
- 한대장 / 대학생 장학금 자동 매칭 · 신청 플랫폼
- **대표 문장** (`05_대표문장.md`)
- 공동대표 조세현(경희대 재학) · 이선주(한국외대 재학)
- 캡쳐: 앱 홈 화면

### 2 — 흩어진 공고, 놓치는 장학금
- 스탯 4: 190여 개교 [공개] / 185만 명 [공개] / 수만 건·년 [추정] / 0원(마감 누락 시)
- 키워드: 탐색 비용 · 학생 전가 | 서식 다운로드 · 수기 반복 | 기존 서비스 · 조회에서 종료
- 핵심 문구: **마감 누락 = 소득 손실**

### 3 — 프로필 1회 → 신청서 완성
- 1 등록 (프로필 1회) / 2 매칭 (12개 신호) / 3 신청 (원본 동일 서식)
- 핵심 문구: HWP · PDF 신청서 자동 해석 → 앱 서식 58종
- 캡쳐: 온보딩 학교 자동추천

### 4 — 매칭 엔진 · 적합도
- 12개 신호 · 자격 자동 진단
- 4단계 판정 · 요건별 사유 표시
- **적합도 5~99%** · 높은 순 정렬
- 마감 D-day · 마감 후 목록 자동 정리
- 핵심 문구: **"된다/안 된다"가 아니라 "왜"까지 — 추측 없음**
- 캡쳐: 매칭 목록(적합도 배지) / 공고 상세(요건별 진단 + D-day)

### 5 — 신청 완결
- 앱 내 서식 작성 · 58종 · 프로필 자동 채움
- 서류 보관함 · 8슬롯 · 기기 내 저장 · 재사용
- 접수 채널 4종 · 이메일 / 재단 / 양식 / 포털
- 원버튼 · 내용 복사 + 제출처 열기
- 캡쳐: 신청서 작성 화면 / 서류 보관함 / 제출 버튼

> **이 장이 대표 문장의 근거다.** "신청서까지 대신 써 준다"는 이 발표에서 가장 큰 주장이고,
> 5번 캡쳐가 그 증거다. 대본에서 가장 공들여야 할 장.

### 6 — 가동 중
- 스탯 6: 45 캠퍼스 / 613 공고 / 171 매칭 / 58 서식 / 93 기관 / 30회 연속
- 표 「서면 제출 후 2일」: 42→45 · 600→613 · 166→171 · 56→58
- 핵심 문구: **증가분에 사람 개입 0 — 서면을 읽으신 이틀 동안 로봇이 채운 숫자입니다**

### 7 — 관리자 페이지 7탭
- 오늘 할 일 / 공고 전체 / 컨펌 작업대 / 양식 / 수집망 / 로봇 / 데이터 품질
- 접근 이중 잠금 (허용 계정 + 일회용 코드)
- 핵심 문구: **인원이 늘어도 개발자를 거치지 않는다**
- 캡쳐: 오늘 할 일 / 컨펌 작업대

### 8 — 게시판 3유형 대응
- 정적 (2시간/교) / 동적 (1~2일/교) / 클릭형 (실제 클릭 채집)
- 핵심 문구: 후발 격차 3~6개월. 축적 자체가 자산

### 9 — 개인정보 아키텍처
- 현재: 단말 저장 · 전송 경로 없음 · 상시 서버 없음
- 회원 후: 매칭 단말 유지 · 서버는 계정 id + 공고 id만 · 로그인 선택
- 핵심 문구: **수집하지 않으면 유출되지 않는다 — 규제 대응은 설계의 결과**

### 10 — 수익 · 시장
- 학생 무료 / 대학·재단 유료
- ① 대학 SaaS 1,200~3,000만 원/교 → 3년차 30개교 5억
- ② 재단 게재·매칭 50~300만 원/건 → 3년차 60건 1억
- TAM 38억 / SAM 9억 / SOM 2,400만 [전부 목표치]
- 핵심 문구: 도입 근거 = 집행률 · 수혜율 대학 평가지표

### 11 — 팀 · 로드맵 · 마무리
- 2명 / 5주 / 480회+ / 0원
- 1Q 2,000명 → 2Q 파일럿 2개교 → 3Q 최초 매출 → 4Q ARR 0.5억
- 병목 = 사업장 주소 → 입주하면 해소
- 마무리: **공고를 모으는 일은 끝냈습니다. 이제 계약을 시작할 주소가 필요합니다.**
