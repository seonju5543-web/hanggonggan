## 왜 GitHub이 아니라 Cloudflare인가 (1분 설명)

관리자 화면은 학생 앱(앱1)과 **다른 주소**에 있어야 합니다. 이유가 세 가지입니다.

1. **잠글 수 있습니다.** Cloudflare는 "허용한 이메일만 입장"을 설정만으로 걸어 줍니다.
   로그인하면 그 메일로 **일회용 코드**가 날아오고, 그 코드를 넣어야 들어옵니다.
   누가 언제 들어왔는지 기록도 남습니다. GitHub Pages로는 이게 안 됩니다.
2. **학생 앱과 저장 공간이 분리됩니다.** 같은 주소에 두면 브라우저가 둘을 한 사이트로 보고
   저장 공간을 공유합니다. 주소가 다르면 관리자 화면에 무슨 일이 생겨도 학생 자료에 닿지 않습니다.
3. **무료입니다.** 푸시 서버(`server/push/`)와 같은 곳이라 계정도 하나면 됩니다.

**학생 앱(앱1)은 그대로 둡니다.** 옮기는 것은 관리자 화면뿐이라 학생에게는 아무 변화가 없습니다.

## 1단계 — Cloudflare에 화면 올리기 (15분)

> **푸시 서버를 올릴 때 쓰신 그 계정 그대로** 쓰시면 됩니다 (새로 가입할 필요 없음).

1. https://dash.cloudflare.com 에 로그인 (계정이 없으면 이메일만으로 무료 가입)
2. 왼쪽 메뉴 **Compute** → **Workers & Pages** → **Create** → 위쪽 **Pages** 탭 →
   **Connect to Git**
   > **메뉴 이름 주의**: 새 대시보드에서는 예전의 `Workers & Pages`가 **`Compute`** 안으로
   > 들어갔습니다(2026-08-06 푸시 서버 올릴 때 실측). `Workers & Pages`가 안 보이면
   > **Compute**부터 눌러 보세요.
   >
   > 그리고 **위쪽 `Pages` 탭을 꼭 누르세요.** 그냥 Create를 누르면 Workers(서버) 쪽으로
   > 만들어져서 화면이 안 뜹니다. 우리가 올리는 건 서버가 아니라 **화면**입니다.
3. `seonju5543-web/hanggonggan` 저장소를 고릅니다
4. 설정을 이렇게 넣습니다

   | 항목 | 값 |
   |---|---|
   | Production branch | `claude/nice-heisenberg-WESq5` |
   | Build command | `bash _admin/build.sh` |
   | Build output directory | `_admin/dist` |

5. **Save and Deploy** → 몇 분 뒤 주소가 나옵니다 (예: `https://hanggonggan-admin.pages.dev`)

이 주소를 열면 아직은 **누구나 볼 수 있습니다.** 2단계에서 잠급니다.
(단, 열쇠를 넣기 전에는 아무 내용도 표시되지 않게 만들어 두었습니다.)

### ⚠️ 바로 이어서 해야 하는 설정 — 빌드 감시 경로

**Settings → Build → Build watch paths** 의 *Include paths* 에 아래 다섯 줄을 넣으세요.

```
_admin/*
data.js
forms.js
verify/entry-rules.cjs
collector/url-key.mjs
```

**왜 필요한가**: 수집 로봇이 하루에 열 번쯤 이 저장소에 공고를 커밋합니다. 그대로 두면
그때마다 관리자 화면을 처음부터 다시 만들어서, 무료 한도(월 500회)를 며칠 만에 다 씁니다.
위 경로만 감시하게 하면 **관리자 화면을 실제로 고쳤을 때만** 다시 만듭니다.

## 2단계 — 두 사람만 들어올 수 있게 잠그기 (10분)

1. 왼쪽 메뉴 **Zero Trust** → 처음이면 무료 플랜(Free) 선택
2. **Access → Applications → Add an application → Self-hosted**
3. 도메인을 이렇게 넣습니다 — **Subdomain 칸에 별표 하나**가 핵심입니다

   | 칸 | 값 |
   |---|---|
   | Subdomain | `*` |
   | Domain | `hanggonggan-admin.pages.dev` (1단계에서 나온 주소) |

   > 별표를 빼면 미리보기 주소만 잠기고 **진짜 주소는 열린 채로 남습니다.**

4. **Policy** 하나를 만듭니다

   | 항목 | 값 |
   |---|---|
   | Policy name | `개발자만` |
   | Action | Allow |
   | Include | **Emails** → 선주님 메일, 공동작업자 메일 두 개 |

5. 저장하고 그 주소를 다시 열어 보세요. **이메일을 넣으라는 화면**이 뜨고,
   메일로 온 코드를 넣어야 들어와집니다. 이게 원래 원하시던 그 방식입니다.

> **메일이 안 왔다고 당황하지 마세요** — 코드 메일은 `noreply@notify.cloudflare.com`에서 오는데
> **Gmail이 스팸함이나 '프로모션' 탭으로 자주 보냅니다.** 거기부터 확인하세요.
>
> 무료 등급으로 50명까지 됩니다. 사람이 늘면 Include에 메일만 추가하면 됩니다.

## 3단계 — 열쇠 만들기 (5분)

화면에 들어가면 GitHub 열쇠를 한 번 넣어 달라고 합니다. 이 열쇠는 **바꾸기 버튼**을 위한 것입니다.

### 선주님 (저장소 주인)

1. GitHub → 오른쪽 위 프로필 → **Settings** → 맨 아래 **Developer settings**
2. **Personal access tokens → Fine-grained tokens → Generate new token**
3. 이렇게 넣습니다

   | 항목 | 값 |
   |---|---|
   | Token name | `한대장 관리자` |
   | Expiration | 90 days (지나면 새로 만들면 됩니다) |
   | Repository access | **Only select repositories** → `hanggonggan` 하나만 |
   | Permissions → Actions | **Read and write** |
   | Permissions → Contents | **Read-only** |

4. 만들어진 열쇠(`github_pat_...`)를 복사해 관리자 화면에 붙여넣습니다

### 공동작업자 (Josehyeon)

**위 방식은 안 됩니다.** 세밀 권한 열쇠(fine-grained)는 **자기가 가진 저장소에만** 붙어서,
남의 저장소용으로는 만들 수 없습니다. 대신:

1. **Developer settings → Personal access tokens → Tokens (classic) → Generate new token**
2. 범위(scope)는 **`repo`** 와 **`workflow`** 두 개만 체크
3. 만들어진 열쇠(`ghp_...`)를 관리자 화면에 붙여넣습니다

*(classic 열쇠는 권한을 이 저장소 하나로 좁힐 수 없습니다. 그래서 **만료일을 반드시 짧게**
두고, 화면의 '열쇠 지우기'를 쓰는 습관을 들이는 편이 좋습니다.)*

> **왜 파일 쓰기 권한을 안 주나요?**
> 이 열쇠가 새어도 남이 저장소 내용을 마음대로 바꾸지 못하게 하기 위해서입니다.
> 관리자 화면의 변경은 **검사를 통과해야만 저장되는 정해진 절차**로만 이루어집니다.

## 버튼을 누르면 실제로 무슨 일이 일어나나

```
버튼 누름
  → 정해진 검사 절차를 깨움 (GitHub Actions '관리자 조정')
  → 요청대로 데이터를 고침
  → 기존 감사 도구로 전수 검사          ← 여기서 걸리면
  → 통과하면 저장 / 실패하면 통째로 되돌림  ← 아무것도 안 바뀜
  → 배포 로봇이 학생 앱까지 올림
```

그래서 **잘못된 내용이 학생 앱에 나가는 경로가 없습니다.** 화면에는 진행 상황이
"반영 중 → 반영 완료 / 실패(사유)"로 표시되고, 모든 변경은 **누가·언제·무엇을**이
기록되어 '데이터 품질' 화면의 변경 이력에서 볼 수 있습니다.

## 화면 여섯 개

| 화면 | 무엇을 하나 |
|---|---|
| **오늘 할 일** | 눌러야 할 것만 모아 놓은 첫 화면 |
| **공고 전체** | 등록된 전부를 조건 없이 · 상태·학교·성격·접수방법·경고등으로 걸러 보기 |
| **컨펌 작업대** | 왼쪽 앱1 내용 / 오른쪽 공고 원문을 나란히 놓고 확인 후 컨펌 · 중복 합치기 |
| **양식** | 신청서 목록과 **실제로 생성되는 문서 미리보기** · 스키마화 대기 큐 |
| **수집망** | 학교별 수집 상태 · 게시판 주소 넣기 · 로봇 즉시 실행 · 리포트 전문 |
| **데이터 품질** | 규칙 위반 · 금액/마감 미확인 · 죽은 링크 · 변경 이력 |

## 막혔을 때 — 실제로 걸리는 것들

| 증상 | 원인 · 해결 |
|---|---|
| 빌드가 실패한다 | 출력 폴더를 `_admin/dist`로, 명령을 `bash _admin/build.sh`로 정확히 넣었는지 확인. 프로덕션 브랜치는 `claude/nice-heisenberg-WESq5` (슬래시 포함) |
| 메뉴에 **Workers & Pages**가 없다 | 새 대시보드는 **Compute** 안에 들어 있습니다 |
| **Pages 탭**이 안 보인다 / Worker가 만들어졌다 | Create를 누른 뒤 **위쪽 `Pages` 탭**을 먼저 눌러야 합니다. 잘못 만들어졌으면 그 프로젝트를 지우고 다시 하세요 (푸시 서버 `handaejang-push`는 건드리지 마세요) |
| 화면은 뜨는데 **버튼이 "실행 요청이 거부됐습니다 (404)"** | 워크플로 파일이 **기본 브랜치**에 있어야 GitHub이 실행을 받아 줍니다. Claude에게 "관리자 워크플로 기본 브랜치에 올려줘"라고 하세요 |
| 버튼이 **401/403** | 열쇠가 만료됐거나 권한이 모자랍니다. Actions가 **Read and write**인지 확인 (공동작업자는 classic + `workflow`) |
| 로그인 코드 메일이 안 온다 | **스팸함·프로모션 탭**을 보세요 (`noreply@notify.cloudflare.com`). 코드는 10분 뒤 만료됩니다 |
| 진짜 주소가 안 잠긴다 | Access 애플리케이션의 **Subdomain 칸에 `*`** 를 넣었는지 확인 |
| 빌드가 하루에 몇 번씩 돈다 | 빌드 감시 경로를 안 넣은 것입니다 (1단계 뒤 ⚠️ 절) |
| 화면에 숫자가 하나도 없다 | 정상입니다 — 열쇠를 넣기 전에는 아무것도 그리지 않습니다 |

무엇이든 화면에 나온 문구를 그대로 알려 주시면 원인을 잡아 드립니다.

## 알아 두실 것

- **관리자 화면은 학생 주소에 절대 뜨지 않습니다.** `_admin` 폴더는 밑줄로 시작해서
  GitHub Pages가 배포하지 않습니다. 이게 깨지지 않았는지 **로봇이 매일 확인**하고,
  혹시 노출되면 🚨 이슈로 알립니다.
- **화면을 고칠 때마다 Cloudflare가 알아서 다시 올립니다** (저장소에 push하면 자동).
- **열쇠는 기본적으로 탭을 닫으면 사라집니다.** "이 기기에 기억하기"를 체크했을 때만 남고,
  언제든 오른쪽 위 '열쇠 지우기'로 지울 수 있습니다.
- 공고 데이터 자체(어떤 장학금이 있는지)는 학생 앱이 읽어야 하므로 **원래 공개**입니다.
  잠기는 것은 정리된 관리자 화면과 조작 기능입니다.
