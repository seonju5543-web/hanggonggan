# 원문 링크 확인 로봇 실행 트리거 (push-to-run · 워크플로 link-check.yml)
#
# ⭐ 이 로봇의 일: 앱이 보여 주는 원문 링크(정식 등록·실시간 공고·재단·지자체·대외활동·공모전·교내 소식)를
#    학생처럼 새 탭으로 열어, 그 공고가 실제로 뜨는지 본다. **주소는 고치지 않는다** — 다른 날 두 번 같은
#    문제를 보면 data/link-check.json 에 적고, 앱은 그 링크 이름을 정직하게 바꿔 보여 준다.
#
# 이 파일을 고쳐 기본 브랜치에 push 하면 한 번 돈다. 아래 설정은 **그 실행에만** 쓰인다
# (매일 예약 실행은 늘 전부를 본다 — 누가 줄을 남겨 둬도 예약이 한 사이트에 묶이지 않게).
#
# only:    (선택) 사이트 주소 조각 하나만 — 예: gachon.ac.kr. 줄이 없으면 전부 ← 기본값
# max:     (선택) 이번에 최대 몇 건 열어 볼지 (기본 400 — 실제로는 20분 예산이 먼저 끊는다)
# perHost: (선택) 한 사이트에서 최대 몇 건 (기본 8 — 학교 서버를 몰아치지 않으려고)
# mode:    (선택) candidates — 원문 후보(collector/link-candidates.json · 우리 기록의 같은 제목 글 · 층2 재단 글 짝)만 열어 본다.
#          후보는 한 사이트에 한 번 실행 3건까지라, 남은 후보를 그날 더 보고 싶을 때 쓴다(앱 링크 전부를 다시 두드리지 않는다).

run: 2026-10-03 — 첫 실행 (원문 대신 홈페이지·게시판 목록이 열리던 사고 · 앱의 원문 링크 전부를 학생처럼 열어 본다)

run: 2026-10-04 — 원문 후보만 한 번 더 (첫 후보 실행이 사이트당 3건 상한으로 남긴 경희 소식 5 · 가천 2 · 서울교대 1)
mode: candidates
